# BlockMemoryAgent 项目说明

> 从零开始理解本项目的导览文档。基于当前代码实际状态（已迁移到 go-kratos Blades）编写。

## 1. 这是什么

BlockMemoryAgent 是一个 **Go 多 Agent 编排系统**，核心理念：用"会话块隔离 + 记忆外部化"解决长上下文遗忘和 Skill 爆炸问题。

- **四层 Agent 层级**：MetaAgent → DomainAgent → SubDomainAgent → Assistant（SubDomain 自适应触发，仅复杂跨层任务启用）
- **5 路径智能路由**：规则层 + LLM 兜底，80% 简单任务不进入四层编排（`router.go`）
- **Plan-and-Execute + Self-Reflection**：DomainAgent 多任务生成结构化计划，助手执行后轻量模型评估不达标重试一次（`plan.go`，feature flag 默认关）
- **三层存储**：PostgreSQL（持久记忆）+ Redis（工作区热缓存）+ pgvector（向量检索）
- **双入口**：HTTP Web UI（Vue SPA）+ bubbletea TUI
- **leaf 执行**：go-kratos Blades（`ModelProvider` + `Agent` + 原生 function-calling）
- **上层编排**：自研三层图状态机（不依赖任何框架的图抽象）

一句话定位：不是 Agent 脚手架，而是一套让 AI 拥有"清晰记忆"和"专注力"的认知架构。

## 4. 核心架构

### 4.1 四层 Agent 层级

```
MetaAgent (Layer 1, 调度中枢)
  │  ClassifyTask 5 路径路由 → 按路径分派 → 监控 → 汇总
  ▼
DomainAgent (Layer 2, 领域管理)
  │  管理单领域上下文 → (可选)生成 ExecutionPlan → 派发助手 → 汇总
  │  (复杂跨层任务触发 SubDomainAgent)
  ▼
SubDomainAgent (Layer 2.5, 子领域，自适应启用)
  │  DomainAgent 的并行子分支（shouldSplitToSubDomains 检测跨子领域边界）
  ▼
Assistant (Layer 3, 任务执行)
     固定角色(code/ui/test/doc...) 或 动态创建
     用 Blades Agent + function-calling 真正干活（写文件/跑命令）
     执行后 Self-Reflection 评估，不达标带反馈重试一次
```

**关键设计**：
- **5 路径路由**（`router.go`）：`direct_tool`（0层，MetaAgent 自跑工具）/`direct_assistant`（1层，建助手）/`create_domain`（2层，单领域）/`multi_domain`（2层×N，并行）/`full_four_layer`（4层，启用 SubDomain）。规则层零 LLM → LLM 兜底 → 安全兜底（`create_domain`，零回归）
- **会话块（SessionBlock）**：每个 DomainAgent 拥有独立上下文块，互不污染。`types.SessionBlock` (`pkg/types/role.go:101`)
- **调用栈（CallStack）**：支持 DomainAgent→SubDomain→Assistant 嵌套调用。`ThreeLayerState.CallStack` (`:132`)
- **角色权限**：`RoleConfigFile.CanCall` (`pkg/config/role_config.go:111`) 限制谁能调谁
- **公共执行原语**（`agent_common.go`）：`CommonExecuteAssistantTask`/`CommonCreateAssistantForTask`/`CommonMatchFixedAssistant`/`CommonCollectTaskSummaries`，消除 Domain/SubDomain/MetaAgent 重复代码
- **多层 Agent 结果摘要**：Assistant 输出 `AgentResult{SummaryForUser, MemoryForMeta}` → SubDomainAgent（可选）块摘要 → DomainAgent 块摘要 → MetaAgent 会话级最终回复。四级摘要与四层 Agent 架构对应，不是 Episode 存储层的四级压缩。
- **跨块记忆同步（R7/R8）**：块完成时通过 `Mailbox` 向其他活跃块发 `MsgInfo`；新块创建 / DomainAgent / SubDomainAgent 启动时自动合并 `state.MetaMemory`；`collectBlockResult` 更新会话级 MetaMemory 后同步到所有活跃块，避免跨域失忆。

### 4.2 图执行引擎 (`internal/graph/three_layer_graph.go`)

`ThreeLayerGraph.Invoke()` 是状态机循环（max 200 步）：

```
current = "MetaAgent"
loop:
  node = resolveNode(current)           # 静态节点 or 动态实例节点
  state = node.Invoke(ctx, state)       # 节点返回新状态 + NextAction
  next = determineNext(current, state)  # 根据 NextAction 路由
  if NextAction == Finish: return
  current = next
```

**NextAction 控制信号** (`pkg/types/types.go:106`)：
- `Continue` — 回到上层（Assistant→DomainAgent→MetaAgent）
- `Switch` — 跳到 `TargetRoleID`
- `Escalate` — 进 `EscalationHandler` 仲裁
- `Finish` — 进 `sinkerNode` 终止

**节点类型**：
- 静态：`MetaAgentNode` / `EscalationHandlerNode` / `sinkerNode`
- 动态：`DomainAgentNode` / `SubDomainAgentNode` / `AssistantNode`（按实例 ID 解析，`resolveInstanceNode` `:224`）

### 4.3 Leaf 执行：Blades 工具循环 (`internal/graph/llm_tools.go`)

Assistant 真正干活走 `executeWithTools`，现已用 Blades 原生 function-calling：

```go
provider := modelFactory.GetBladesProvider(ctx, roleDef.ID)
tools := buildBladesTools(executor, progress, sessionID, agentName, &results)
agent, _ := blades.NewAgent(agentName,
    blades.WithModel(provider),
    blades.WithInstruction(systemPrompt),
    blades.WithTools(tools...),
    blades.WithMaxIterations(toolCallMaxRounds)) // 默认 50，config.yaml 可配（当前 100），由 agent.tool_call_max_rounds 控制
output, _ := blades.NewRunner(agent).Run(ctx, blades.UserMessage(userMsg))
```

Blades `Agent.Run` 内部跑 ReAct：`model.Generate` → 检测 `ToolPart` → `tool.Handle` → 回灌 → 直到无 tool call 或达 maxIterations。`blades_agent_runner.go` 额外通过 `loopDetector` 检测重复调用/空转，提前优雅退出并返回已收集结果，避免无限循环。

**7 个内置工具** (`internal/graph/blades_tools.go`)：`ReadFile`/`WriteFile`/`ListDir`/`RunCommand`/`SearchInFiles`/`HTTPGet`/`HTTPPost`，用 `tools.NewFunc` 自动生成 JSON schema，复用 `ToolExecutor` 沙箱实现。

**完成门控**：当 LLM 在最终输出中声称已写入文件（如"已写"/"created"/"saved"），但工具结果中没有成功的 `WriteFile` 时，返回 `Error: "missing WriteFile result"` 触发上层重试。

**Mock 路径**：无 API Key 时 `GetBladesProvider` 返回 error，退化为单次 `llm.Generate`；但因启动期校验 LLM 连通性，无有效 key 时服务无法启动。

### 4.4 记忆系统 (`internal/memory/`)

4 阶段管线，**独立于 Blades**（Blades `Session` 仅管叶子 ReAct 短上下文，长期记忆全自研）：

| 阶段 | 文件 | 职责 |
|---|---|---|
| Write | `write.go` | Episode 重要性评分 + 话题绑定 |
| Compress | `compress.go` | 2 级压缩：Raw → Standard |
| Search | `search.go` | 多信号相关性：pgvector 语义 + 实体重叠 + 因果链 + 时间衰减 |
| Assemble | `assembler.go` | 4 段上下文组装（System/TopicGlobal/SharedState/PrivateMemory）+ TokenBudget |
| Snapshot | `snapshot.go` | Redis 热加载 + Postgres 持久化，归档幂等兜底（`archived` atomic 标记 + `switchToNextBlock` 切块前补写） |

**压缩层级** (`pkg/enums/enums.go`)：
- `LevelRaw` — 完整原始记录
- `LevelStandard` — 摘要（丢弃 FullObservation）

**块记忆向量检索**（特性3）：DomainAgent 执行后块记忆落库 + 向量化，需要时从向量库召回最相似块回灌上下文。

> 注：原"DomainAgent 归档复用"（特性4，`store/domain_archive.go`）已在 P1-1/P0-5 删除——其与块记忆同表存两份近同内容、生命周期割裂，故合并为单一块记忆机制（`KnowledgeTypeDomainArchive` 常量保留作历史数据兼容）。

**启动期维度校验**：`ValidateEmbeddingDimension` 校验 `global_knowledge.embedding` 列维度与配置一致，不一致 `log.Fatalf`（避免维度不匹配导致 SaveKnowledge 静默失败）。

### 4.5 运行时聚合 (`internal/runtime/runtime.go`)

单一 `Runtime` 结构，进程级共享，注入到 graph 节点：

```go
type Runtime struct {
    Boards   *board.Manager      // 任务看板（MetaAgent 建，所有 Agent 观察全局状态）
    Mailbox  *mailbox.Mailbox    // 跨 Agent 消息（广播 + 定向转发）
    Skills   *skill.Registry     // Skill 池 + 按领域装配子集
    Soul     *soul.Loader        // 人格 (soul.md) + 温度策略
    Watchdog *watchdog.Watchdog  // 上下文长度看门狗
}
```

- **Board** (`internal/board/`)：MetaAgent 在 `handleInitial` 创建 `TaskBoard`，顶层子任务 = 推断的领域名。Agent `MarkDone`/`MarkFailed`
- **Mailbox** (`internal/mailbox/`)：跨 Agent 事件。`processMailbox` 处理广播桶并按领域扇出；`meta_sync.go` 在块完成时主动向其他活跃块发 `MsgInfo`，Domain/SubDomain Agent 启动时通过 `applyMailboxToBlock` 消费并注入块级 `MetaMemory`。
- **Skill** (`internal/skill/`)：`Pool` → `FilterByDomain` → LLM `AssembleSet`(≤8) → `Registry.Bind(agent)`；只把子集 brief 注入 assistant system prompt
- **Soul** (`internal/soul/`)：`soul.md` 人格注入 + 按任务类型选温度（路由 0 / 代码 0.15 / 创意 0.8）
- **Watchdog** (`internal/watchdog/`)：每轮 `MetaAgentNode.Invoke` 顶部 `runWatchdog` 评估上下文规模，超软阈值建议压缩

## 5. 启动流程

`backend/main.go` 仅做 flag 解析、文件日志、HTTP 监听与优雅关闭；所有依赖装配委托 `internal/testserver.BuildHandler`（生产二进制与集成测试共用同一份 wiring）。`BuildHandler` 内部步骤：

```
1. flag 解析 (-config -roles -env -soul -skills)
2. config.LoadEnvFile(.env) → config.Load(config.yaml)
3. store.NewPostgresStore(dsn)   # 失败则启动失败并明确报错
   store.NewRedisStore(addr,...)  # 同上
   store.EnsureSessionHistorySchema      # 幂等自动建 session_history
   store.EnsureSessionEventsSchema       # 幂等自动建 session_events
   store.EnsureInitialMemorySchema       # 幂等自动建 001 记忆/知识表 + step_count 列
   # 注：004 session_logs 与 005 meta_memory 列不在自动迁移覆盖内，需通过 migrations/*.sql 应用
4. pkgconfig.LoadRoleConfig(roles.yaml)
5. model.NewModelFactory(roleCfg).WarmUp(ctx)  # 预热 meta+domain 模型
6. graph.NewRoleRegistry + NewRoleFactory
7. skill.LoadFromYAML(skills.yaml)  # 失败则启动失败
8. runtime.New(soulPath, skillPool)
9. graph.NewMetaAgentNode + NewEscalationHandlerNode + sinkerNode
   builder.SetModelFactory/SetRuntime/AddNode → Build()
10. server.NewSessionManager(graph, registry)
    sessionMgr.RestoreSessions(ctx, 50)  # 从 session_history 恢复历史
11. memory.NewSnapshotManager(redis, pg)  # 快照管理器
12. server.NewAPIHandler 注入各依赖
13. mux 注册路由 → http.ListenAndServe(:10010)
14. 等待 SIGINT/SIGTERM → 关闭
```

**严格启动原则**：配置文件（config/roles/env/soul/skills）缺失，或 PostgreSQL / Redis / LLM 后端不可达，服务器启动失败并明确报错。所有基础设施必须在启动前可用。

## 10. 关键设计决策

1. **Blades 仅在 leaf**：上层 graph 状态机自研，因为 Blades 的 Flow/Graph 抽象无法表达 CallStack/SessionBlock/Escalate 四层嵌套语义。Blades 负责"单 Agent + 工具循环"这块通用能力。

2. **记忆分两层**：Blades `Session`（in-memory）管叶子 ReAct 短上下文；自研 4 阶段管线管长期记忆（PG/Redis/pgvector）。Episode 存储按设计文档简化为 2 级压缩（Raw/Standard），由 `compression_level` 列区分。

3. **会话块隔离**：每个 DomainAgent 一个 `SessionBlock`，上下文不串。这是"专注力"的核心——单个 Agent 只看自己领域的记忆，不被其他领域污染。

4. **跨块记忆同步（R7/R8）**：隔离不等于失忆。块完成时通过 `Mailbox` 主动通知其他活跃块；新块创建 / Agent 启动时自动继承 `state.MetaMemory`；`collectBlockResult` 更新会话级 MetaMemory 后同步到所有活跃块。实现"块内聚焦、块间可见"的折中。

5. **完成门控**：当 LLM 在最终输出中声称已写入文件（如"已写"/"created"/"saved"），但工具结果中没有成功的 `WriteFile` 时，返回 `Error: "missing WriteFile result"`，由上层触发重试；不再使用 `"[失败:...]"` 魔法字符串前缀做控制流。

6. **串行派发助手**：`dispatchAssistantsSerial`（`domain_agent.go:224`）——子任务常有依赖（"启动游戏"依赖"写代码"），并行会导致后续任务找不到前置产物。串行虽慢但成功率高。

7. **严格启动**：`config.yaml` / `roles.yaml` / `.env` / `soul.md` / `skills.yaml` 任一配置文件缺失，或 PostgreSQL / Redis / LLM 后端不可达，启动即失败并明确报告缺失/不可达项。不再支持零配置降级启动。

8. **SSE 实时性**：`ProgressCallback` 把 graph 每步（思考/意图/工具调用/token）实时推给 Web/TUI，`server/tui_broadcaster.go` 镜像到 SSE 订阅者。

9. **5 路径路由瘦身**（`router.go`）：80% 简单任务（纯 QA / 单工具 / 单领域）不进入四层编排。规则层零 LLM 成本覆盖 60%+，LLM 兜底用轻量模型，安全兜底 `RouteCreateDomain` 保持原有复杂任务行为零回归。

10. **SubDomain 自适应**：`shouldSplitToSubDomains` 从恒 `false` 改为读 `state.EnableSubdomain` + `detectSubdomainBoundaries`（规则 + 可选 LLM），仅 `RouteFullFourLayer` 启用第四层，避免单领域任务不必要的 overhead。

11. **Plan-and-Execute + Self-Reflection**（`plan.go`，feature flag 默认关）：DomainAgent 多任务时调重量模型生成 `ExecutionPlan`（步骤列表 + tool_hint），按步骤顺序派发助手，支持断点续行（`PendingGoals`/`MarkDone`）；`CommonExecuteAssistantTask` 内置 `reflectOnResult` 轻量模型评估，不达标带反馈重试一次（仅一次防死循环）。

12. **死循环防护**：多层渐进告警，LLM 调用追踪器（`llm_tracker.go`）统一覆盖超时/慢速模式/Token 统计，按天分割日志。

> 注：原决策"DomainAgent 归档复用"（`store/domain_archive.go`）已在 P1-1/P0-5 删除，合并为单一块记忆机制。

13. **默认关闭的机制为预留扩展**：SubDomainAgent（`full_four_layer`）、Plan-and-Execute（`plan_enabled`）、Self-Reflection（`reflection_enabled`）、DAG 调度（`dag_enabled`）、Board/Watchdog/CmdQueue 等当前默认关闭或仅占位，代码保留是因为它们对应后续能力（跨子领域并行、计划执行、定时任务、Agent 间协作），并非当前主干的必需路径。启动时不激活这些机制不会影响核心 MetaAgent → DomainAgent → Assistant 流程。
    - 例外：`Mailbox` 虽由 `Runtime` 初始化，但当前已被 `meta_sync.go` 用于跨块结果通知（R7）；`MetaMemory` 跨块注入（R8）也已默认启用。

## 15. 常见问题

**Q: 没有 API Key 能跑吗？**
不能。启动时会校验 LLM 连通性，无 key 或后端不可达会启动失败。需要配置有效的 OPENAI_API_KEY 与 OPENAI_BASE_URL。

**Q: 必须装 PostgreSQL + Redis 吗？**
必须。两者缺失会导致启动失败。请通过 docker compose 启动并应用 migrations 后再运行服务。

**Q: Web UI 怎么构建？**
`cd web && pnpm install && pnpm build`，产物到 `web/dist/`，`main.go` 直接 serve。开发模式可 `pnpm dev` 起独立 Vite 服务，API 代理到 `:10010`。

**Q: 怎么加新助手角色？**
在 `config/roles.yaml` 的 `fixed_roles[]` 加一项，设 `type: fixed` + `model_config` + `system_prompt` + `can_be_called: true`。重启生效。

**Q: 怎么加新工具？**
在 `internal/graph/blades_tools.go` 加 input struct + `tools.NewFunc` 包装，handler 内调 `ToolExecutor` 新方法（在 `tool_executor.go` 实现）。

**Q: 温度怎么动态调？**
`soul.Temperature(kind, default)` 按任务类型（Routing/Code/Creative）选温度，`BladesClient.GenerateWithOptions` 临时构造新 provider 完成（`openai.NewModel` 构造廉价）。
