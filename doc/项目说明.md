# BlockMemoryAgent 项目说明

> 从零开始理解本项目的导览文档。基于当前代码实际状态（已迁移到 go-kratos Blades）编写。

## 1. 这是什么

BlockMemoryAgent 是一个 **Go 多 Agent 编排系统**，核心理念：用"单一 ReAct 主循环 + 异步子 Agent 工具分发"解决长上下文遗忘和 Skill 爆炸问题。

- **ReAct 主循环**：MetaAgent 运行单一 LLM → 工具循环；层级关系通过 `call_sub_agent` 工具递归涌现
- **异步子 Agent 分发**：`call_sub_agent` 起 goroutine，结果通过 `Mailbox` 异步回灌父 Agent
- **权威 Agent 树**：`internal/domain/orchestrator/tree.go` 维护派发树快照，HTTP 暴露 `/api/sessions/{id}/tree` 读 + `/api/sessions/{id}/agents/{aid}/cancel` 取消子 Agent
- **块记忆事实提取**：子 Agent 完成后调轻量模型提取 1-5 条关键事实，每条单独向量化落库，替代原始 result.Text 整段落库
- **历史压缩**：每 N 轮 ReAct 迭代 `compressHistory` 把中段历史压成"系统前缀 + 用户目标 + 摘要 + 最近 K 条"，防 token 爆炸
- **共享记忆**：主 Agent 经 `WriteSharedMemory` 写关键上下文到 `sharedKV`，子 Agent 自动读取，避免重读全文件
- **验证闭环编排器**：`verifyloop` 原生驱动"产出 -> 自测 -> 修正 -> 上级统一测试"状态机，不依赖主 Agent 提示词
- **两段事件流记忆**：主 Agent 事件 + 子 Agent 事件，无压缩 / 无 RAG / 无向量检索
- **三层存储**：PostgreSQL（会话历史/事件）+ Redis（工作区热缓存）+ pgvector（保留，未来可接 RAG）
- **双入口**：HTTP Web UI（Vue SPA）+ bubbletea TUI
- **leaf 执行**：go-kratos Blades（`ModelProvider` + 原生 function-calling）
- **上层编排**：自研 ReAct 循环 + 工具注册表（不依赖图状态机）

一句话定位：不是 Agent 脚手架，而是一套让 AI 拥有"清晰记忆"和"专注力"的认知架构。

## 4. 核心架构

### 4.1 ReAct 主循环与异步子 Agent

```
User
 │
 ▼
MetaAgent (ReAct loop)
 │  LLM.Generate(system prompt + history + tools)
 │  ├─ 工具调用：ReadFile / WriteFile / RunCommand / ...
 │  └─ call_sub_agent(role_id, task) ──► goroutine
 │                                      │
 ▼                                      ▼
回答用户                        DomainAgent / fixed role (ReAct loop)
                                    │
                                    ├─ 工具调用
                                    └─ call_sub_agent(...) ──► Assistant
                                                               │
                                                               └─ 工具调用
```

**关键设计**：
- **单一主循环**：`internal/agent/react_agent.go` 中 `ReActAgent.RunWithHistory` 实现 LLM → 工具 → 结果 → 循环，直到纯文本回答。
- **层级即调用栈**：MetaAgent 调 `call_sub_agent(domain_agent, ...)`，DomainAgent 再调 `call_sub_agent(code_assistant, ...)`；Go 调用栈本身就是层级关系，无需 `CallStack`/`SessionBlock`/`NextAction` 状态机。
- **异步分发**：`internal/domain/subagent/dispatcher.go` 中 `call_sub_agent` 工具起 goroutine 跑子 Agent，立即返回 `sub_agent_id`；子 Agent 完成后把摘要推 `Mailbox`。
- **Mailbox 轮询**：父 Agent 每轮 LLM 前 `Drain` 自己的邮箱，把子 Agent 摘要注入上下文。
- **角色权限**：`domain/role.Registry.CanCall` (`pkg/config/role_config.go`) 限制谁能调谁；`roles.yaml` 的 `can_be_called` / `parents` 字段直接映射工具可用性。
- **事件流记忆**：`domain/memory.Pipeline` 记录 `tool_call` / `call_sub_agent` / `sub_agent_summary` / `answer` 事件；`Assemble` 注入最近 N 条作为上下文。

### 4.2 执行引擎（已重构为 ReAct）

> 历史：`internal/graph/ThreeLayerGraph` 四层状态机已删除。原 `MetaAgentNode` / `DomainAgentNode` / `SubDomainAgentNode` / `AssistantNode` / `router.go` / `role_factory.go` 等代码已移除，逻辑折叠进 ReAct 主循环 + `call_sub_agent` 工具。

`internal/agent/react_agent.go`：

```go
for i := 0; i < maxIter; i++ {
    messages := memory.Assemble(role, agentID, history)
    resp := llm.Generate(ctx, system, messages, tools.Schema())
    history = append(history, assistantMessage(resp))

    if resp has no tool calls {
        memory.Write(answer)
        return result
    }

    for _, tc := range resp.ToolCalls {
        result := tools.Dispatch(ctx, tc)
        memory.Write(tool_call)
        history = append(history, toolResultMessage(result))
    }
}
```

### 4.3 Leaf 执行：Blades 工具循环 (`internal/domain/tool/`)

ReActAgent 直接使用 Blades 原生 function-calling：

```go
req := &blades.ModelRequest{
    Instruction: blades.SystemMessage(system),
    Messages:    history,
    Tools:       toolRegistry.Schema(),
}
resp, _ := llm.Generate(ctx, req)
```

`domain/tool.Registry.Schema()` 用 `tools.NewFunc` 为每个内置工具生成 JSON schema；`Registry.Dispatch` 通过名称查找并执行工具，复用 `Executor` 沙箱实现。

**14 个内置工具** (`internal/domain/tool/builtin.go` + `registry.go` + `shared_memory.go`)：
- 文件/命令：`ReadFile` / `WriteFile` / `ListDir` / `RunCommand` / `SearchInFiles`
- HTTP：`HTTPGet` / `HTTPPost`
- Git：`GitDiff` / `GitStatus` / `GitLog` / `GitBlame`
- 共享内存：`WriteSharedMemory`（仅 MetaAgent 白名单，写 `sharedKV`）
- Agent 通信：`call_sub_agent`（`domain/subagent.Dispatcher` 注册，支持 `domain` 字段定制展示名）、`send_message`（任一 Agent 向另一 Agent 邮箱投递请求/通知/回复）

**角色工具白名单**：`NewToolRegistryAdapterWithFilter` 按角色限制可调工具集。DomainAgent 开放完整读/写/执行/HTTP/共享内存权限（承担上下文采集 + 任务拆分 + 派发执行）；MetaAgent 限制为 `call_sub_agent` + `WriteSharedMemory` + `HTTPGet`，防越位读全文与原文粘贴。`call_sub_agent` 入参 `task` 上限 2000 runes，超限报错并提示"规格写入 `WriteSharedMemory`，task 只写目标 + 验收标准"。

`ReadFile` 重复读限制为 session 级：同一会话内已读文件拒绝重读（最多 5 个不同文件），新用户消息时 `ResetReadHistory` 清空记录，确保限制为单任务级而非整个会话级。

**Mock 路径**：`ReactService.SetModelProvider` 支持注入 mock `blades.ModelProvider`；生产环境通过 `model.ModelFactory.GetBladesProvider` 获取真实 provider。启动期 `VerifyConnectivity` 会校验 LLM 连通性。

### 4.4 记忆系统 (`internal/domain/memory/`)

ReAct 架构采用**两段事件流**，不再使用 4 阶段管线：

| 阶段 | 文件 | 职责 |
|---|---|---|
| Write | `pipeline.go` | 追加 `MemoryEvent` 到 agent 事件流，可选持久化 |
| Assemble | `pipeline.go` | 注入最近 N 条事件作为系统上下文 |

**事件类型**：
- `tool_call` — 工具名、输入、输出
- `call_sub_agent` — 调用了哪个子 Agent、任务摘要
- `sub_agent_summary` — 子 Agent 完成摘要（来自 Mailbox）
- `answer` — 最终用户回答

**Legacy 保留**：`internal/memory/write.go` 仍负责 Episode 持久化，但已不在 ReAct 主循环热路径上。`compress.go` / `search.go` / `assembler.go` / `snapshot.go` / `callback.go` / `block_vector.go` / `workspace_adapter.go` 已删除。

**启动期维度校验**：`ValidateEmbeddingDimension` 校验 `global_knowledge.embedding` 列维度与配置一致；不一致时返回错误，由 `bootstrap.Build` 包装后中止启动（避免维度不匹配导致 SaveKnowledge 静默失败）。pgvector 表保留，未来可重新接入 RAG。

**嵌入实现（pseudo 决策，2026-08-10）**：当前 `config/roles.yaml` `embed.provider: pseudo`——字符哈希假向量（`embed/pseudo.go`），块记忆召回为**字符哈希近似而非语义检索**（用户方舟账号未激活 doubao-embedding 且 EMBEDDING_API_KEY 鉴权失败，无法接真实 embed）。此状态为显式接受并记录：召回质量受限但零依赖离线可用；外部知识库检索（TODO #27）将使用独立配置的真实 embed provider，不动块记忆 pseudo 召回。

### 4.5 运行时聚合 (`internal/runtime/runtime.go`)

单一 `Runtime` 结构，进程级共享，在 `bootstrap.Build` 中构造：

```go
type Runtime struct {
    Boards   *board.Manager      // 任务看板
    Mailbox  *mailbox.Mailbox    // Agent 间异步邮箱
    Skills   *skill.Registry     // Skill 池 + Agent→SkillSet 装配映射
    Soul     *soul.Loader        // 人格加载器（soul.md + 温度策略）
    Watchdog *watchdog.Watchdog  // 上下文长度看门狗（软/硬阈值）
    CmdQueue *cmdqueue.Manager   // 用户指令队列（抢占中断 / 队列注入）
}
```

**当前接线现状**（ReAct 重构后，各组件接入程度不一）：
- **Mailbox** (`internal/mailbox/`)：**活跃在主路径上**。bootstrap 把共享邮箱同时注入 `runtime`、子 Agent 调度器与 `NewReactService`；`call_sub_agent` 完成后把摘要推 Mailbox，父 Agent 每轮 LLM 前 `Drain` 自己的邮箱并注入上下文。
- **Board** (`internal/board/`)：经 `/api/sessions/{id}/board` 与 TUI 面板展示，未接入 ReAct 主循环。
- **Skill** (`internal/skill/`)：技能池在启动时加载，`/api/skills` 可查；`AssembleSet`/`Bind` 的 prompt 装配尚未接入 ReAct 路径。
- **Soul** (`internal/soul/`)：soul.md 正常加载，人格名经 API 暴露；尚未注入 ReAct prompt。
- **Watchdog** (`internal/watchdog/`)：软/硬阈值经 `agent.Query(QueryKindWatchdog)` 与 `/api/sessions/{id}/watchdog` 暴露；未在主循环逐 tick 执行。
- **CmdQueue** (`internal/cmdqueue/`)：经 `/api/sessions/{id}/enqueue`、`/interrupt` 端点使用。

### 4.6 共享记忆 / 历史压缩 / 验证闭环 / LLM 调用日志（阶段 1-9 增量）

**共享记忆（`domain/memory/kv.go` + `domain/tool/shared_memory.go`）**：`memory.NewInMemoryKV(writable, store)` 创建进程内 KV；主 Agent 经 `WriteSharedMemory` 工具写入关键上下文（文件路径/行号/函数签名/前置结论/验收标准），bootstrap 把同一 `sharedKV` 注入 `Dispatcher.WithKVMemory`（子 Agent 读只视图）与 `toolRegistry.SetSharedMemory`（工具后端）。`Dispatcher.injectKVMemory` 按 `parentID:shared` 键读取并注入子 Agent 任务前缀，实现"协程 Agent 共享主 Agent 记忆"。锁防 panic，defer unlock，不持锁调外部代码。

**历史压缩（`domain/memory/pipeline.go` `compressHistory`）**：每 `summarize_every` 步（默认 5）触发，把中段历史压成 system 前缀 + 用户任务目标 + 中段摘要 + 最近 `summarize_keep_recent` 条（默认 10）。`history_max_messages`（默认 30）是单次 LLM 请求携带的滑动窗口上限（`react_agent.go` `windowMessages`）。三者配合防长会话 token 爆炸。部分缓解 TODO #4"长会话事件流膨胀"（在 ReAct 层而非 watchdog 层）。

**权威 Agent 树（`internal/domain/orchestrator/tree.go`，2026-07-30 落地）**：ReAct 重构后子 Agent 由 Dispatcher 直接 goroutine 创建,不注册为 `AgentInstance`,原"层级即调用栈"丢 introspect/cancel 能力。补 `Tree` struct 作元数据层:Dispatcher 派发前 `Register` 节点 + `SetCancel` 绑定 cancel func,完成时 `Finish` 写终态;HTTP 暴露 `GET /api/sessions/{id}/tree` 返回快照(含 ID/ParentID/Role/Status/Started/Finished/Summary/Err),`POST /api/sessions/{id}/agents/{aid}/cancel` 调 cancel func 取消子 Agent。`context.CancelFunc` 幂等,与 goroutine `defer cancel()` 重复调用安全。树不持久化,服务重启清空,TUI `deriveSubAgentNodes` 保留作 fallback。`verifyloop.ExecuteChild` 同步路径暂不入树(phase 2)。

**块记忆事实提取（`subagent.FactExtractor` 接口，2026-07-30 落地）**：`saveBlockMemory` 原存原始 result.Text 整段,召回污染上下文且语义模糊。改为先调轻量模型提取 1-5 条关键事实,每条单独落 `KnowledgeRecord` 独立向量化。`bootstrap/fact_extractor.go` `llmFactExtractor` 复用 `ModelFactory.CallLightweightWithRetry`;`ParseFactsJSON` 兼容纯数组/markdown 围栏/含前后文本三种 LLM 输出格式。提取失败或返回空自动回退原始保存(`saveRawBlockMemory`),不丢结果。未注入时保持原行为。

**验证闭环编排器（`domain/verifyloop/`）**：原生状态机驱动"产出 -> 自测 -> 修正 -> 上级统一测试"，不依赖主 Agent 提示词。三接口解耦：`Verifier`（SelfTest/UnifiedTest 返回结构化 `Verdict`）+ `Fixer`（修正产出）+ `Reporter`（上报结果）。`AgentVerifier`/`AgentFixer`/`MailboxReporter` 是默认实现，`NewWith` 支持自定义注入。`PlanConfirmVerifier` 可选接口实现"测试方向不明确 -> 列方案 -> 产出方确认 -> 符合才自测"前置步骤。`[VERIFY:PASS/FAIL]` 标记确定性解析；`maxRounds` 往返上限防死循环；ctx 取消快速返回。bootstrap 按 `verification_role_pairs` 配置（默认 `[{code_assistant, test_assistant}]`）注册多个 `OnSubAgentDone` 钩子；`assistant_self_test_enabled` / `domain_self_test_enabled` 默认关闭。

**LLM 调用日志（`agent/service_react.go` `sessionLogger`）**：每次 LLM 调用 I/O 写入 `session_logs` 表；`QueryKindLogs` 查询类型支持按会话回看完整调用链。`LiveEventTokenUsage` 事件类型实时推送 token 用量到 SSE/TUI。DeepSeek V4 适配：`provider_deepseek.go` 兼容 `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens` 与 `reasoning_content` 字段。

**硬 Token 预算（`agent/react_agent.go` `RunWithHistory`，规划中见 `doc/TODO.md` #8）**：`maxIter=50` 仅防死循环，无累计 token 上限。`token_budget_per_goal`（默认 0=不限，推荐 100000）在 `RunWithHistory` 每轮 LLM 调用后累加 `resp.Message.TokenUsage.TotalTokens` 到 `cumulativeTokens`，超限则 break 循环并返回 `[系统] Token 预算耗尽（已用 {cumulativeTokens} / {budget}）。已完成部分：{lastAnswer}`。与 `LiveEventTokenUsage` 配合，前端可实时显示预算条。`ContextExplodeHardLimit` 限单次输入，`token_budget_per_goal` 限单目标累计，两者正交。

**块记忆沉淀**：`Dispatcher.saveBlockMemory` 在子 Agent 成功完成时沉淀结果摘要；`blockMemorySaver` 适配 `PostgresStore.Embed + SaveKnowledge`；`config.block_memory_write_enabled`（默认 true）控制开关。`pipeline.WithMaxEventsPerAgent` + `InMemoryStore.WithMaxEventsPerAgent` 防事件流无限增长；`runSubAgent` defer `mailbox.Purge` 修子 Agent 收件箱泄漏。

**领域任务拆解（`domain/assembly/` 已删，见 `doc/TODO.md` #10）**：旧 `Splitter`/`Executor`/`Aggregator` 三接口 + `Assembly` 编排器零引用已删。当前 DomainAgent 走原生工具权限方案（直接在 ReAct 循环内做上下文采集 + 拆分 + 派发）。

**长任务稳定性修复（2026-08-02，TUI 塔防实战验收驱动）**：连续多轮 TUI 实战（在 `workspace/` 从零生成塔防小游戏）暴露并修复一批长任务卡顿/死锁缺陷，最终一轮 Agent 一次交付完整产物，全量 `go test ./...` 绿（详见 `doc/TODO.md` #16）。

1. **入史工具入参截断**（`react_agent.go` `truncateToolCallInputsForHistory`）：assistant 入史/持久化/续跑回发用截断副本（单字符串值 2000 runes，附原始长度标记），派发执行仍用原始入参。破"WriteFile 全文逐轮重发 → 单轮 input 100K+ → 续跑预算一次耗尽 → pause/resume 零进展"死锁。
2. **滑动窗口下刀条件**（`windowMessages` + `pipeline.go` `compressHistory`）：由"锚 user 边界"改为"只避开孤立 tool 结果"。工作型历史窗口内常无 user，锚 user 走空窗口致上下文塌缩成 2 条消息（实证：配置 Agent 每轮失忆重写 config.js 不收敛）。
3. **暂停态可取消**（`service_react.go` `cancel()`）：放开 `awaiting_clarify`/`paused_on_child`，原仅 running 可取消，暂停死锁无逃生通道。
4. **RunCommand 移出探索预算**（`tool/registry.go`）：exploreBudget 只计 ReadFile/ListDir（上限 8）。RunCommand 是验证/动作工具，计入会让 Agent 写完文件后无法验证，在"必须验证"与"工具被拒"间死循环。
5. **重复派发去重**（`dispatcher.go` `findPendingDomainSibling`）：`call_sub_agent` 派 domain 角色时查权威树快照，同父 Agent 下同 domain 子 Agent Running/Paused 即拒绝并提示等 mailbox 回传（实证：渲染引擎重复派发×3，并发写同一批文件互相覆盖）。拒绝先于限额计数，不烧派发配额；domain 为空不去重。
6. **递归派发终结保护**（`runSubAgentOnce`/`ResumePaused` 注入 `WithPendingChildrenChecker`）：子 Agent 派发自己的子 Agent 后须等 mailbox 回传再终答（实证：domain 拆两个子任务后直接 DONE，父把中间状态误当终答，会话 completed 但产出缺失）。bootstrap 同步注入 `WithMessagesStore`（暂停恢复前置）。
7. **预算/超时配置**：`token_budget_per_role` domain/meta 400K、叶子助手 100K（原 120K/40K，扛不住多文件 codegen 一次交付）；`sub_agent_timeout_min` 30→60。
8. **TUI 工作目录展示**：`tui/model.go` 加 `workDir`（`currentWorkDir()`），顶栏与欢迎页 Workspace 显示真实路径（原硬编码 `~/demo`）。

## 10. 关键设计决策

1. **Blades 仅在 leaf**：Blades 负责"单 Agent + 工具循环"这块通用能力（`ModelProvider` + 原生 function-calling）；上层编排是自研 ReAct 主循环，不依赖任何图状态机框架。

2. **层级即调用栈**：MetaAgent → 子 Agent 的层级关系通过 `call_sub_agent` 工具递归涌现——子 Agent 是 goroutine 里独立运行的 ReAct 循环，Go 调用栈本身就是层级，无需 `CallStack`/`SessionBlock`/`NextAction` 状态机。子 Agent 完成后摘要经 `Mailbox` 异步回灌父 Agent 上下文。

3. **两段事件流记忆**：`Write` 记录 tool_call / call_sub_agent / sub_agent_summary / answer 事件，`Assemble` 在 LLM 调用前注入最近 N 条。无压缩、无 RAG、无向量检索，刻意保持简单；当前默认 `InMemoryStore`，Postgres 事件持久化见 `doc/TODO.md` #3。

4. **会话持久化，默认全新启动**：会话历史（goal/summary/工具结果）与事件流写 `session_history`/`session_events`；每次启动默认是全新会话列表（旧会话可在同 ID 查询时从 PG 回退读取），需要恢复时设 `agent.restore_sessions: true` 才在启动时把最近 50 个会话载入内存。

5. **严格启动**：`config.yaml` / `roles.yaml` / `.env` / `soul.md` / `skills.yaml` 任一缺失，或 PostgreSQL / Redis / LLM 后端不可达，启动即失败并明确报告缺失/不可达项。不支持零配置降级启动。

6. **统一装配**：所有 wiring 集中在 `bootstrap.Build`，HTTP 服务、TUI、集成测试（`testserver` 薄封装）共用同一份初始化路径，避免行为分叉。

7. **SSE 实时性**：`toolRegistry.SetProgressCallback` 把工具执行事件实时回流到会话事件流，`server/tui_broadcaster.go` 镜像给 SSE 订阅者，Web/TUI 同步渲染。

8. **死循环防护**：ReAct 主循环 `maxIter` 硬上限（默认 50）；`internal/model/` LLM 调用追踪器统一覆盖超时/慢速模式/Token 统计；内存会话数上限 20，超出淘汰最早完成的会话。

9. **结构化日志统一**：各组件通过 `SetLogger` 注入 `*logger.Logger`，错误类日志输出 `[ERRO]` 并可附调用栈；`store` 包用窄接口 `store.Logger` 避免与 `logger` 循环导入；入口把标准库 `log` 输出兜底转发为统一格式。

10. **工具沙箱**：`domain/tool` 的 `sandbox.go`/`guards.go` 做写路径逃逸检测与危险命令黑名单，可通过 `agent.tool_sandbox_*` 配置白名单与追加黑名单。

11. **默认关闭/预留机制**：`dag_enabled` 有完整实现但默认关；`plan_enabled`/`reflection_enabled`/`interrupt_enabled`/`queue_inject_enabled`/`human_clarify_enabled` 的实现已随旧 graph 删除，配置字段待清理（`doc/TODO.md` #5）；Board/Skill/Soul/Watchdog 保留在 `Runtime`，当前仅部分接线（见 §4.5）。

12. **历史压缩防 token 爆炸**：`compressHistory` 每 `summarize_every` 步（默认 5）把中段历史压成"系统前缀 + 用户目标 + 摘要 + 最近 K 条"；与 `history_max_messages` 滑动窗口配合，避免长会话上下文线性增长导致的 token 成本激增与注意力衰减（对应"上下文一膨胀模型变笨"的痛点）。

17. **硬 Token 预算防烧钱**：`token_budget_per_goal`（默认 0=不限，推荐 100000）在 `RunWithHistory` 每轮 LLM 调用后累加 `TotalTokens`，超限 break 循环返回"Token 预算耗尽 + 已完成部分"。`maxIter=50` 仅防死循环不防烧钱；`ContextExplodeHardLimit` 限单次输入，本字段限单目标累计，三者正交。规划中见 `doc/TODO.md` #8。

13. **共享记忆跨 Agent 传递**：`WriteSharedMemory` + `sharedKV` 让主 Agent 把采集到的关键上下文（文件路径/行号/函数签名/前置结论/验收标准）写入 KV，子 Agent 经 `Dispatcher.injectKVMemory` 自动读取任务前缀，避免每个子 Agent 重读全文件。`task` 入参 2000 runes 上限强制规格写入共享记忆而非任务正文。

14. **角色工具白名单**：`NewToolRegistryAdapterWithFilter` 按角色限制可调工具集。MetaAgent 只能 `call_sub_agent` + `WriteSharedMemory` + `HTTPGet`，防越位读全文与原文粘贴；DomainAgent 开放完整读/写/执行/HTTP/共享内存权限，承担上下文采集 + 任务拆分 + 派发执行。`ReadFile` session 级重读限制 + `ResetReadHistory` 在新用户消息时清空。

15. **验证闭环原生编排**：`verifyloop` 把"产出 -> 自测 -> 修正 -> 上级统一测试"做成原生状态机，不依赖主 Agent 提示词驱动。`Verifier`/`Fixer`/`Reporter` 三接口解耦，支持多场景复用（`ComputerUseVerifier`/`CLIVerifier`/`MCPVerifier` 留扩展口子）。`PlanConfirmVerifier` 可选接口实现"测试方向不明确 -> 列方案 -> 产出方确认 -> 符合才自测"前置步骤。`maxRounds` 防死循环；ctx 取消快速返回。

16. **LLM 调用全链路日志**：`sessionLogger` 把每次 LLM I/O 写 `session_logs`，`QueryKindLogs` 支持按会话回看完整调用链；`LiveEventTokenUsage` 实时推送 token 用量。`provider_deepseek.go` 适配 DeepSeek V4 缓存模式（`prompt_cache_hit_tokens`/`prompt_cache_miss_tokens`）与思考模型 `reasoning_content` 字段。

> 历史注记：旧 graph 时代的"会话块隔离""跨块 MetaMemory 同步（R7/R8）""完成门控""5 路径路由""Plan-and-Execute"等机制已随 `internal/graph/` 一并删除，相关设计理念见 `doc/设计文档_v3.md`。

## 14. 常见问题

**Q: 没有 API Key 能跑吗？**
不能。启动时会校验 LLM 连通性，无 key 或后端不可达会启动失败。需要配置有效的 OPENAI_API_KEY 与 OPENAI_BASE_URL。

**Q: 必须装 PostgreSQL + Redis 吗？**
必须。两者缺失会导致启动失败。请通过 docker compose 启动并应用 migrations 后再运行服务。

**Q: Web UI 怎么构建？**
`cd web && pnpm install && pnpm build`，产物到 `web/dist/`，`main.go` 直接 serve。开发模式可 `pnpm dev` 起独立 Vite 服务，API 代理到 `:10010`。

**Q: 怎么加新助手角色？**
在 `config/roles.yaml` 的 `fixed_roles[]` 加一项，设 `type: fixed` + `model_config` + `system_prompt` + `can_be_called: true`。重启生效。

**Q: 怎么加新工具？**
在 `internal/domain/tool/builtin.go` 参考现有内置工具注册；执行能力在 `executor.go` 实现，沙箱约束在 `sandbox.go`/`guards.go` 配置。工具会自动进入 `Registry.Schema()` 供 LLM function-calling 使用。

**Q: 向量模型怎么配置？**
在 `config/roles.yaml` 的 `embed` 段配置（已从 `config.yaml` 迁移）：

```yaml
embed:
  provider: pseudo          # pseudo（默认）| openai | local
  model: ""                 # openai/local 时填写，如 text-embedding-3-small、bge-m3、doubao-embedding
  api_key: ${EMBEDDING_API_KEY:""}
  base_url: ${EMBEDDING_BASE_URL:""}
  batch_size: 1
```

- `provider: pseudo` 为字符哈希，零外部依赖，适合测试/开发。
- `provider: openai` 调用 OpenAI 兼容 `/v1/embeddings`，适用于 OpenAI、DeepSeek、豆包/火山方舟等。
- `provider: local` 同样走 OpenAI 兼容协议，用于 ollama、xinference 等本地服务。
- 向量维度必须与 `pgvector.dimensions` 一致。

豆包 Embedding 示例：

```yaml
embed:
  provider: openai
  model: doubao-embedding        # 你在方舟开通的 Embedding 模型名
  api_key: ${EMBEDDING_API_KEY}
  base_url: https://ark.cn-beijing.volces.com/api/v3
  batch_size: 1
```

**Q: 怎么用本地 ollama 跑模型？**
在 `config/roles.yaml` 对应角色的 `model_config` 中：

```yaml
model_config:
  provider: ollama
  model: qwen2.5:14b        # 你本地 pull 的模型名
  api_key: ""
  base_url: "http://localhost:11434"   # Ollama 原生 /api/chat，不需要 /v1 后缀
```

ollama 需已启动。Embedding 如需走本地，使用 `embed.provider: local` 并配 `base_url: http://localhost:11434/v1`（Embedding 仍走 OpenAI 兼容协议）。

**Q: 豆包（火山方舟/火山引擎）模型怎么配？**
豆包提供 OpenAI 兼容接口，统一按 `provider: openai` 配置，把 `base_url` 指向豆包方舟的兼容端点：

```yaml
model_config:
  provider: openai
  model: doubao-lite-4k      # 或你开通的豆包模型名
  api_key: ${DOUBAO_API_KEY} # 方舟 API Key
  base_url: https://ark.cn-beijing.volces.com/api/v3  # 以你开通的地域端点为准
  temperature: 0.5
  max_tokens: 4096
```

Embedding 同理：

```yaml
embed:
  provider: openai
  model: doubao-embedding   # 你开通的豆包 Embedding 模型名
  api_key: ${DOUBAO_API_KEY}
  base_url: https://ark.cn-beijing.volces.com/api/v3
```

只要对方端点兼容 `/v1/chat/completions` 与 `/v1/embeddings`，就不需要单独实现 provider。

**Q: Moonshot / Kimi 模型怎么配？**
Kimi 提供 OpenAI 兼容接口，统一按 `provider: openai` 配置：

```yaml
model_config:
  provider: openai
  model: kimi-K2.7-code          # 或 kimi 系列其他模型名
  api_key: ${KIMI_API_KEY}       # Moonshot API Key
  base_url: https://api.moonshot.cn/v1
  temperature: 0.5
  max_tokens: 4096
```

> 注意：不要把 `provider` 写成 `anthropic`，也不要把 `base_url` 写成 `https://api.deepseek.com/anthropic`。`anthropic` provider 仅用于通过 OpenAI 兼容网关访问 Claude，不适用于 Kimi。

**Q: Plan-and-Execute / Self-Reflection 还在吗？**
实现已随旧 `internal/graph/` 一并删除（`plan.go` 不复存在），`agent.plan_enabled` / `reflection_enabled` 仅是待清理的配置残留（见 `doc/TODO.md` #5）。当前执行模型就是 ReAct 主循环 + `call_sub_agent` 异步分发。

**Q: 温度怎么动态调？**
`soul.Temperature(kind, default)` 按任务类型（Routing/Code/Creative）选温度，`BladesClient.GenerateWithOptions` 临时构造新 provider 完成（自研 provider 构造廉价）。
