# 上下文工程改进点 - 基于Anthropic Claude Code 80%提示词删除实践

> 参考文章：[Claude删掉了 80% 提示词，然后呢？](https://mp.weixin.qq.com/s/RBr5C6-ThCS1pmLPWbwX4g)
> 核心论点：模型越强，越要把判断交给模型。从"禁令驱动"转向"环境+边界+判断交给模型"。
> 核查对象：`config/roles.yaml` + `CLAUDE.md` + `internal/domain/tool/registry.go` 工具描述
> 核查日期：2026-07-28

## 文章 6 转向速览

1. **规则 -> 环境判断**：从"列规则禁令"到"描述环境+目标+边界，让模型自行判断"
2. **工具范例 -> 清晰接口**：从"提示词里示范工具用法"到"把工具参数/状态/边界设计清楚"
3. **预塞信息 -> 渐进披露**：从"所有信息常驻上下文"到"拆成Skill按需加载"
4. **重复强调 -> 正确位置**：从"系统提示词+CLAUDE.md+Skills 重复"到"规则放工具描述一处"
5. **CLAUDE.md 堆放 -> 轻量约定**：从"所有知识堆放处"到"只放无法从代码看出的特殊约定"
6. **简单文字规格 -> 高保真参考**：从"抽象描述"到"测试用例/现有代码/原型"

文章行动建议：打开你的 Agent 系统提示词，找到所有"不许/禁止/绝对不要"，逐条问：这条规则是模型真的不会，还是你不信任它？

## 改进点核查

### 改进点 1 - MetaAgent 提示词与代码白名单重复禁令【转向 1】

**位置**：`config/roles.yaml:31-32`

**现状**：
```yaml
禁止调用 ReadFile / WriteFile / RunCommand / SearchInFiles / ListDir--
你没有这些工具。读文件交给 DomainAgent。HTTPGet 可用于联网查文档/API 参考。
```

**问题**：代码 `internal/domain/role/registry.go:97` 已将 MetaAgent 工具白名单限定为 `["call_sub_agent", "WriteSharedMemory", "HTTPGet"]`，`internal/agent/service_react.go:674,749` `NewToolRegistryAdapterWithFilter` 强制 filter。LLM 拿不到这些工具，禁令冗余。

**文章对照**：转向 1 - "从给Claude列规则到让Claude结合环境自行判断"。代码已强制，提示词重复禁令是"不信任模型"的体现。

**改进**：删除"禁止调用..."整段。保留"HTTPGet 可用于联网查文档/API 参考"作为环境描述（告知可用能力，非禁令）。

---

### 改进点 2 - Fixed Roles 五处重复"你没有 call_sub_agent 工具"【转向 1】

**位置**：`config/roles.yaml:164, 201, 236, 270, 304`（code_assistant / ui_assistant / prompt_reviewer / test_assistant / doc_assistant 各一处）

**现状**：每个 fixed role system_prompt 开头都有"你是叶子执行者：只完成父 Agent 交办的单一任务，不要再派发子任务（你没有 call_sub_agent 工具）"。

**问题**：代码白名单已排除 `call_sub_agent`（`registry.go:97` MetaAgent 才有，fixed roles tools 列表无此工具）。5 处重复禁令，且 LLM 拿不到该工具。

**改进**：删除"（你没有 call_sub_agent 工具）"。保留"你是叶子执行者：只完成父 Agent 交办的单一任务"作为角色定位（环境描述，非禁令）。

---

### 改进点 3 - ReadFile 限制规则过时且三处重复【转向 1+4，最严重】

**位置**：
- `config/roles.yaml:98` DomainAgent：`ReadFile 同一文件不超过 1 次，单次不超 200 行`
- `config/roles.yaml:352` domain_template：`每个助手 ReadFile 不超过 5 次，单次不超过 300 行`
- `config/roles.yaml:371` assistant_template：`单次 ReadFile 不超过 300 行；每个任务累计不超过 5 次`
- `internal/domain/tool/registry.go:403` 工具描述：`同一任务中已读过的文件会被拒绝重读，且最多读取 5 个不同文件`

**代码真相**（已核查）：
- `registry.go:19,336` 明确"maxReadFilePerTask 已废弃，不再限制不同文件数量"。
- 实际限制：单文件重读被拦截（session 级），单次 `ReadFileMaxChars: 4000`（`executor.go:110`, `builtin.go:154`）。
- "200 行 / 300 行 / 5 次" 均为**过时数字**，代码已不强制。

**问题**：
1. 三处提示词数字互相矛盾（200 行 vs 300 行，5 次 vs 不限）。
2. 与代码实际行为（4000 字符上限）不符。
3. 文章转向 4："工具的使用规则应该写进工具描述，而不是同时出现在系统提示词、CLAUDE.md 和多个 Skills 里"。当前规则散布 4 处。

**改进**：
- 删除 `roles.yaml:98, 352, 371` 三处 ReadFile 数字限制。
- 仅在 `registry.go:403` 工具描述中说明真实行为："读取文件内容。path 为路径。同 session 已读文件会返回提示不复读。单次最多 4000 字符。"（改进点见核查报告 §推荐落地项 1）

### 改进点 4 - CLAUDE.md 3k tokens 偏重，含可从代码 derive 内容【转向 5】

**位置**：`CLAUDE.md` 全文约 3k tokens

**现状**：CLAUDE.md 包含：项目介绍、Common commands、Architecture（Entry flow / ReAct execution / Runtime aggregation / Memory / Storage / Model factory / Config / Server UI）、Package Dependency Rules、Conventions。

**问题**：
- "Common commands"（make run / go test 等）可从 Makefile / go.mod derive。
- "Architecture" 详细描述（Entry flow 各步骤、ReAct 执行流程）可从 `doc/项目说明.md` + 代码 derive。
- "Package Dependency Rules" 可从 `docs/superpowers/plans/dependency-rules.md` derive。
- 文章转向 5："CLAUDE.md 应当保持轻量，重点记录无法从代码库直接看出的特殊约定"。

**改进**：
- CLAUDE.md 瘦身到约 1k tokens，只保留：
  - 项目一句话定位（BlockMemoryAgent = Go multi-agent on Blades）
  - 不可从代码看出的约定：`GOTOOLCHAIN=local` 必须设置、Windows bash 路径规范（forward slashes）、strict startup 无降级模式、`doc/项目说明.md` 是权威实现指南（其他 doc 可能漂移）
  - 指向 `doc/项目说明.md` 与 `Makefile`
- 详细架构描述移到 `doc/项目说明.md`（已有，避免重复）。

**收益**：每次会话省 ~2k tokens，长期累积显著；CLAUDE.md 聚焦"模型不知道但必须遵守"的硬约定。

### 改进点 5 - "不要"系列禁令可改为环境描述【转向 1】

**位置**：`config/roles.yaml` 多处

**现状清单**：
- `:40` `禁止把整个领域目标不拆分就丢给固定助手`
- `:67` `不要空等`
- `:111-115` DomainAgent【不要做的事】整段：`不要把整个领域目标不拆分就丢给一个子 Agent` / `不要重复派发同一子任务` / `不要 ReadFile 全文后把原文塞进 task` / `不要把 MetaAgent 注入的共享记忆原文塞进 task`
- `:125` `不要写过程流水账`
- `:351` `禁止多个助手重复全量读取同一份代码`
- `:369-372` assistant_template `禁止一上来大量 ReadFile` / `禁止写临时脚本再次打印已读过的文件内容`

**问题**：文章转向 1 - 旧模型需"禁止/绝对不要"防最坏情况；新模型（glm-5.2 / Claude 5 代）能力足够，可改为环境描述让模型自行判断。

**改进示例**：
- `禁止把整个领域目标不拆分就丢给固定助手` → `固定助手是叶子执行者，不读上下文不拆分；整块任务需 DomainAgent 拆到单函数级再派。`
- `不要 ReadFile 全文后把原文塞进 task` → `task <= 500 字，只写目标+验收；规格原文走 WriteSharedMemory。`
- `不要写过程流水账` → `最终答复 = 结论先行 + 文件路径 + 验收证据。`

从"你不许做这些事"变成"环境是这样，你自己判断"。

### 改进点 6 - 工具描述应承担工具使用规则【转向 2+4】

**位置**：`internal/domain/tool/registry.go:399-420` Schema 函数中各工具描述

**现状**：ReadFile 工具描述（`:403`）含使用规则；WriteFile 描述（`:414`）含 temporary 字段说明。但 `call_sub_agent` 工具描述未含 `task <= 500 字` / `role_id="domain" 必填 domain 字段` 等契约，这些契约散布在 MetaAgent 与 DomainAgent 提示词中。

**问题**：文章转向 2 - "与其在提示词里反复示范工具怎么调用，不如把工具的参数、状态和边界设计清楚"。转向 4 - "工具的使用规则应该写进工具描述"。

**改进**：
- `call_sub_agent` 工具描述加入：`task 自包含 <= 500 字（背景+目标+验收）；规格原文走 WriteSharedMemory；role_id="domain" 时必填 domain 字段（领域简称，用于展示名）；立即返回 sub_agent_id，结果经 mailbox 异步回灌。`
- `WriteSharedMemory` 工具描述加入：`content 写入跨领域共享上下文（项目路径/整体规划/验收标准），被派发的子 Agent 自动读取。规格原文走这里，不塞进 task。`
- 删除提示词中重复的 task 契约说明。

**收益**：工具接口自描述，提示词瘦身，规则单点维护。

---

### 改进点 7 - Skills 按需加载未接线【转向 3】

**位置**：`internal/skill/` + `internal/runtime/runtime.go`

**现状**（CLAUDE.md 记载）：Skill pool 已加载，`AssembleSet`/`Bind` prompt 装配 **NOT wired** into ReAct path。`/api/skills` 仅暴露池列表。

**问题**：文章转向 3 - "代码审查、验证流程等内容不需要常驻上下文，可以拆成独立 Skill，在任务真正需要时再加载"。当前 Skill 机制存在但未接线，相当于按需加载能力闲置。

**改进**：评估是否在 ReAct 循环中接入 Skill 按需加载。但这属于功能开发（非提示词工程），优先级低于改进点 1-6。可列为 TODO。

**注意**：当前 system_prompt 已较长，若 Skill 接线后能把部分提示词内容拆为 Skill，效果更佳。

---

### 改进点 8 - dynamic_template prompt 过时且禁令密集【转向 1+4】

**位置**：`config/roles.yaml:341-374` domain_template + assistant_template

**现状**：
- `:352` `每个助手 ReadFile 不超过 5 次，单次不超过 300 行` - 过时数字
- `:369-373` assistant_template 5 条禁令密集：`禁止一上来大量 ReadFile` / `同一文件禁止重复读取` / `单次 ReadFile 不超过 300 行` / `禁止写临时脚本再次打印已读过的文件内容` / `连续两次工具调用无新信息...立即停止`

**问题**：
1. 过时数字（300 行 / 5 次）误导。
2. `同一文件禁止重复读取` 代码已强制（`registry.go:330-334`），禁令冗余。
3. 5 条禁令全是"不要"，与文章"给模型松绑"理念相反。

**改进**：
- 删除过时数字与代码已强制的禁令。
- `连续两次工具调用无新信息...立即停止` 可保留，但改为环境描述："若工具调用无新信息，及时收敛返回结论。"
- 整体 dynamic_template prompt 建议重写为环境描述风格。
