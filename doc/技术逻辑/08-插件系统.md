## 8.1 四种插件形态与生命周期

- `builtin`：进程内 Go 插件（程序化注册）；
- `mcp`：外部 MCP server（stdio 子进程 / streamable HTTP / docker 容器）；
- `bundle`：Claude/Codex 插件目录包（`.claude-plugin/plugin.json` + `.mcp.json` + `skills/*/SKILL.md`）→ 展开为若干 mcp 插件 + skill 条目；
- `service`：Docker 长驻 HTTP 服务（无工具注入，只有生命周期与健康探针，如 Open Design）。

**Plugin 接口**：`Manifest()/Init(ctx,deps)/Start(ctx)/Stop(ctx)/Tools() []tool.Tool`（Init/Start 不得注册工具；注册/摘除由 Manager 负责）。`Manifest{ToolNames 静态声明（mcp 实际以 ListTools 为准）, Roles, RequiresEnv, TopLevel}`——`TopLevel=true` 表"顶层必备"（config `settings.top_level` 声明，mcpbridge 透传），由 `Manager.TopLevelTools()` 收集供会话顶层 scope 预挂载；`VisibleForRole`：Roles 空或含 `"*"` → 全可见。

状态机：`registered → initialized → running → stopped` + `degraded`（MCP 断线）。

## 8.3 加载/启用/停用/降级（manager）

**loadDesired 合并优先级**（低→高）：plugins.yaml（每次重读磁盘）→ `plugins.installed.yaml`（**只补未声明 ID**）→ builtins → bundle 展开（每 server 生成 ID `bundle/<Dir>/<server>`，**默认启用**；yaml 同 ID 深合并）。

**applyDesired**：`reflect.DeepEqual(inst.config, pc)` 差异驱动——不等即"停旧建新"（**只改 enabled 也走重建**）；createInstance 按 Kind 分派（mcp→mcpFactory；builtin→表；service→包内构造）。

**Enable**：幂等（running 短路）→ MissingEnv 检查 → `plugin.Init` → initialized → `Start(lifecycleCtx)` → **工具全有或全无注册**（冲突预检 → 回滚 → Stop）→ running。

**Disable**：Unregister 全部 → cancel → Stop → stopped。

**降级/恢复**：`onBridgeDown`（Unregister 全部 + degraded）/ `onBridgeUp`（逐工具查重后 Register + running）。**但 LifecycleHooks 在生产装配中未接线**（`SetLifecycleHooks` 只有测试调用）→ MCP 断线时插件**显示仍 running**、工具仍在 Registry，直到调用时返回 `execution_failed` +"MCP 连接不可用"。桥内部重连独立运行，重连后旧工具对象仍可用（持 *Bridge 指针，调用时再取 session）；只是**服务端新增/删除的工具不会反映到 Registry**。

**reload 生效时机**：工具可见性下一轮生效（ReAct 每轮读 Schema）；某 Agent 是否看得见叠加：静态白名单 ∪（插件 Roles 可见 ∩ 该 Agent scope 已挂载集），再叠 roleToolGate 硬门（预挂名按 scope 豁免，见 05 5.12）。

**`TopLevelTools()`**（manager.go:531，2026-09-17）：只收 enabled ∧ running ∧ TopLevel 的插件工具名——供 ReactService `mountTopLevelEssentials` 在会话 run/resume 时预挂到顶层 scope（三档全挂）；插件停用/未运行自然缺席，零行为变化。

## 8.4 mcpbridge（MCP 桥）

**Settings**：transport(stdio 默认/http/docker)/command/args/env/url/image/ports/volumes/**shared**/exec_command/container_entrypoint/container_env/destructive/**tool_description_suffix**/**image_passthrough**/roles/**top_level（2026-09-17，顶层必备声明，web_search 已标）**/**exec_timeout_sec（默认 120s）**。

**连接生命周期**：

- `Init`：展开 `${WORKDIR}`（就地改写 volumes）；校验 shared 仅限 docker；按 transport 校验必填。
- `Start`：stopped 时重置（disable→enable 复用同实例）；建自己的 stopCtx；connect；成功存 session/cmd/tools，**初始连接不触发 OnUp**；启 supervise goroutine。
- `connect`：newTransport → client.Connect → ListTools → wrapTool 逐个转 tool.Tool。
- **supervise**（单 goroutine 串行）：`session.Wait()` 返回即断线 → 清字段 → OnDown → **退避重连 1s→2s→…封顶 30s** → connect 成功 → 持锁二次检查 stopped → 写新 session → OnUp(newTools) → 递归 supervise。
- `callTool`：session nil → "MCP 连接不可用（等待重连）"；ExecTimeout 包裹；结果文本经 **`tool.WrapUntrusted("mcp:"+name, text)` 数据围栏**；`ImagePassthrough` 时提取图片（≤4 张/单张 ≤4MiB）。
- `Stop`：幂等；stopped=true + stopCancel + session.Close + killCmd（等 3s 超时强杀）。

**工具命名**：本地注册名强制 `"<插件ID>__<远端名>"`（撞名根治——历史事故：host_computer_use 与 ui_preview 的 browser_find 裸名撞名随机死一方）；`Aliases()` 刻意 nil。

## 8.5 docker 传输两种形态

- **legacy（shared=false）**：容器名 `bma-plugin-<净化id>-<pid>`（pid 后缀=同机多实例各管各，代价=强杀后孤儿容器）；`docker run -i --rm`；killCmd 时 **removeDockerContainer**（`--rm` 在 CLI 被 kill 时不生效）。
- **shared（共享 keeper）**：容器名 `bma-plugin-<净化id>`（**全局确定**）；`docker run -d --entrypoint sleep infinity` 常驻 + `docker exec -i` 起本会话 MCP server；`ensureSharedContainer`（inspect 状态与镜像 → 一致复用/不一致重建；run 失败二次 inspect 兜竞态）；killCmd **只杀 exec CLI 不回收容器**。**按工作目录分容器（2026-09-17）**：带 `${WORKDIR}` 卷的插件，容器名追加工作目录哈希后缀（`dockerSharedContainerName(id, wd)`，fnv-32a 8 位）——`sessionFor` 按调用 ctx 的 workdir 选容器/按需建侧车会话（`closeExtraSessions` 回收），异目录会话的产物不再落错目录；默认目录（Init 时的启动目录）保持无前缀旧名兼容。

## 8.6 service 插件

`Start`：inspect 复用（running 且镜像一致 → waitHealthy + syncFiles）/ 镜像不符重建 / 清残留 → `docker run -d` → HealthURL 时 waitHealthy（默认 60s，2xx 才算）失败则清容器报错 → `syncFiles`（best-effort：`docker exec cat` 读现有 JSON → 深合并（本侧覆盖）→ `sh -c 'mkdir -p … && cat > …'` 写回）。`Stop` = removeContainer。

## 8.7 Agent 自安装闭环（plugin_*）

- **plugin_search**：聚合 ①内置目录 ②已配置实例 ③远程 registry（白名单 `cfg.RegistrySources` 或官方端点；单源 8s、8MiB 上限、按 name 去重取 isLatest；`streamable-http` remote 优先，否则 `npx -y <npm包>`）；截断 30 条；非 config 条目进 searchCache。
- **plugin_install**：`resolveInstall`（目录路径 vs 手工 manifest——**只看 transport/command/url/image 四个 string 字段**；只传 args 的请求会走目录路径丢 args）→ `validateInstall`（ID 正则；拒 `bundle/` 前缀；仅 mcp|service；**destructive 插件必须显式 roles（非空且不含 *）**）→ installMu 串行 + 冲突拒绝 → 原子写 `plugins.installed.yaml`（temp+rename）→ createInstance + Enable → 失败 rollback（Disable→删实例→dropInstalled）。成功后 `Registry.MountForScope` 自动挂进调用者 scope。
- plugin_enable/disable/list 直调 Manager。
- `declaredRoles`：manifest.Roles > settings.roles > `["*"]`。

## 8.8 bundle 插件包

`Scan(dir)`：只处理子目录并按名排序（**保证 Reload 差异稳定**）；非插件包静默跳过。
`loadBundle`：plugin.json（可选，Name 缺省目录名）→ `.mcp.json`（`${CLAUDE_PLUGIN_ROOT}` 全量替换为绝对路径并注入该变量）→ `skills/<name>/SKILL.md`（frontmatter name/description/domain/tags/tool_ref；SkillID = `SanitizeID(dir_name)` 防跨包同名覆盖；正文 >4000 字节截断）。两文件皆无 → 非插件包。
`Manager.syncBundleSkills`：新目录 skill 注册进 skillPool（幂等）；目录消失摘除。

## 8.9 project 包（PROJECT.md / AGENTS.md）

- `EnsureProjectDoc`：**只在文件缺失时生成**（幂等）；`RefreshProjectDoc`：无条件重写 managed 区（`ManagedBegin/End` 标记之间；区外保留人手补充）。
- `LoadProjectDoc`：取标记区正文；缺失/无标记 → 空。
- `scanProject` 输出：# 项目概览（模块探测 go.mod/package.json/Cargo/pyproject）+ Make target（上限 20）+ ## 推荐领域拆分 + ## 文档地图（根级 + doc/ 一级 *.md，上限 30）。
- 领域拆分：LLM `cls.Partition`（清洗臆造路径、未覆盖文件按依赖图簇兜底**永不丢文件**）失败回退 `clusterByDeps`（HTML script/JS import/CSS import/Python import 边解析；节点 >5000 跳过边解析；单文件 >1MiB 只读前 1MiB）+ 启发式命名（**永不返回空 Name**）。
- `FileOutline`（导出供 tool 层复用）：正则启发式符号轮廓（8 条规则、0-3 列缩进、上限 12 符号）。
- 领域种子：`SetDomainSeedHook` → `UpsertDomainProfile(source="project_md")`。
- `LoadProjectBrief`（AGENTS.md 优先 CLAUDE.md）：缓存键绝对路径、指纹 mtime(sec+nsec)+size；**AGENTS.md 存在但不可读 → 返回空不回退 CLAUDE.md**（刻意的优先语义）；截断 maxRunes。

## 8.11 隐含约定与坑

1. **MCP 工具前缀 `__`** 是撞名根治手段——不要去掉。
2. **LifecycleHooks 生产未接线** → 断线状态不精确（显示 running、Registry 留旧工具、服务端工具变化不反映）。
3. **Enable 冲突预检的内层回滚是错位代码**：预检在任何注册之前，`Unregister(tools[j])` 摘的可能是**别的插件注册的同名工具**（当前靠前缀命名规避）。
4. **ctx 双轨**：Bridge 建自己的 stopCtx；子进程绑 Manager 的 lifecycle ctx——Disable 两条取消路径都走才干净。
5. **Init 就地改写 settings.Volumes**（同 map 多实例共享会互污；当前各实例独立）。
6. **两层锁**：Manager.mu（instances map）与 instance.lock（单实例）——不要在持 inst.lock 时取 m.mu 写锁。
7. **shared docker 容器是全局资源**：换项目目录要手动 `docker rm -f bma-plugin-<id>`。
8. **docker run 前必清同名残留**（--rm 在 CLI kill 时不生效）。
9. **roles 权限天花板**：destructive 插件禁止缺省/`["*"]`（install 直接拒）；可见性还要求 running。service 插件不解析 roles。
10. **RequiresEnv 对 mcp 插件实际不生效**（persistInstalled 只写 Kind/EnabledFlag/Settings，mcp 的 Manifest 由 bridge 从 settings 重建只带 Roles）→ mcp 安装条目重启后 MissingEnv 恒空。
11. **bundle 默认启用 vs yaml 普通条目默认不启用**——同配置两种默认值。
12. **plugin_install 只传 args 会被丢弃**（判定手工 manifest 不看 args）。
13. **安装不做覆盖**（同 ID 已存在直接拒，引导改 yaml + reload）。
14. **plugins.d/ 无 fsnotify**，必须显式 reload。
15. **dockerInspectRunning 在 plugins 与 mcpbridge 各一份**（包依赖方向不允许复用）——改行为要改两处。
16. **knowledge.go 是空转抽象**（无实现无调用）。
17. **project 缓存全进程共享无上限**；AGENTS.md 不可读不回退。
18. **Ensure vs Refresh 的脚注文案不同**（非 bug 但产物有细微差别）；Refresh 走去抖（3s）防连写文件反复调 LLM。
19. **LLM 分区清洗规则**：忽略臆造路径/同文件只归首域/空名空文件域丢弃/未覆盖兜底——永不留"待人工标注"。
20. **bundleServerSettings 的 Args/Env 转 []any/map[string]any** 匹配 mcpbridge 类型断言——上游给 []string 会被静默忽略。
21. **Manager.Load 失败语义是 fail-open**（bootstrap 只记日志；插件没起来不阻碍服务启动）。
