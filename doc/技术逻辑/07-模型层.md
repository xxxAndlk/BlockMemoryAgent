## 7.1 职责与文件清单

模型层是"角色 → 可用 LLM 调用句柄"的唯一解析者与生命周期持有者，兜住各家协议差异。

## 7.2 ModelFactory：配置合并与缓存

**缓存**：`models map[roleID 或 roleID+"\x1f"+thinking]cachedClient`；`cachedClient{client, cfg, roleID, thinkingOverride}`——组合键不可反解，**失效重算必须靠 `roleID` 字段**。

**getModel 流程**（factory.go:165-218）：`checkRegistryReload`（**缓存命中也会走**=每次取模型一次 stat）→ 组合键查缓存 → 写锁双重检查 → `resolveConfig` → thinking 覆盖 → api_key 空报错（**不回退 mock**）→ NewBladesClient 写缓存。

**resolveConfig 优先级**（:558-631）：

1. `role_binding`（models.json role_bindings[roleID]）——命中即**直接 return**（角色 model_ref 被忽略）；条目缺失 → **fail-open** 忽略绑定继续。
2. 角色的 `model_ref`——解析不到条目 → **返回 error（严格，不回落内联）**。
3. 内联连接字段（roles.yaml 直填）。
4. base 来源：meta→MetaAgent.ModelConfig；domain→DomainAgent；lightweight→LightweightModel（Model/ModelRef 均空回退 Domain）；其他→动态角色 → fixed_role → Domain 兜底。

`applyModelEntry`：条目 Provider/Model/APIKey/BaseURL **无条件覆盖**（空也覆盖=清空角色侧）；MaxTokens 仅当 `base.MaxTokens<=0 && entry.MaxOutputTokens>0` 时取条目（角色显式上限优先）；ModelRef/Temperature/Thinking 保留角色侧。

## 7.3 Provider 解析链与构造

```
ReactService.providerForRole
  └─ sessionID 非空: GetBladesProviderWithThinking(roleID, sess.currentThinking(), fallbackObserver)
Dispatcher.providerForAgent
  └─ AgentModelOverrider 实现且 agentID 非空 → GetBladesProviderForAgent（实例覆盖优先）
```

- `GetBladesProviderWithFallback`：主 provider 成功后读 `fallbackChainFor(roleID)`（空=零行为变化）；否则包 `newFallbackProvider`。
- `GetBladesProviderWithThinking`：thinking 空→委托；非空→`getModel(roleID, thinking)` + 备胎同档构造（**换备胎不改档位**）；备胎构造**不做连通性探测**（故障现场预探测拖慢解析）。
- 构造链：`createBladesProvider` 按 provider 名分发（openai/openai-chat/openai-deepseek/""→chat；openai-responses；anthropic；ollama）+ `wrapWithRetry`。`BladesClient.doGenerate` **一律走 NewStreaming 取最后非 nil 消息**（ark coding 拒绝非流式长任务）。

**每次 LLM 调用前重解析**：agent 侧 `providerFn` 闭包（react_agent.go:1300-1306），失败保留旧 provider——运行中换模型下一次调用即生效。

## 7.4 四种 provider 实现

| 维度 | openai-chat | openai-responses | anthropic | ollama |
|---|---|---|---|---|
| max tokens 字段 | `max_tokens` 或 `max_completion_tokens`（按模型名前缀） | `max_output_tokens`（**下限 16**） | `max_tokens`（缺省 4096） | `num_predict` |
| thinking | `reasoning_effort`（off→none） | `reasoning.effort` | ThinkingConfig（low 4096/medium 8192/high 16384 budget，**开 thinking 时 temperature 强制 1**） | **不支持** |
| reasoning 回传 | `Metadata["reasoning_content"]` 双向（DeepSeek V4 硬要求） | **刻意不回传** | thinking_delta → Metadata（截 4000 rune） | — |
| 流式 | SSE 累积快照（每事件 yield） | 事件流累积快照 | text_delta 增量 yield + 累积 thinking | **伪流式**（Generate 后 yield 一次） |
| 工具 | tools 嵌套 function；ToolPart↔tool_calls；**content 显式 nil** | 扁平 tools；function_call/function_call_output | 连续 tool_result **合并**为单条 user（否则 400）；tool_result 可挂图片 | ToolPart 结果**拼成文本**；assistant 工具调用**无 ID** |
| 图片 | data URL（image→image_url、video→video_url、audio 丢弃） | **不处理**（静默丢） | base64 image block（MIME 白名单 png/jpeg/gif/webp） | — |
| cache 断点 | — | DeepSeek 原生 cache 字段 / `cached_tokens` | **3 处断点**（system 尾/tools 尾/messages 尾"移动断点"） | — |
| finish_reason=length | **丢 tool_calls 保文本** | 同左 | 续写 8 轮耗尽后丢 tool_use | `done_reason==length` 同左 |
| 错误串 | `openai-chat %d: %s`（**400 后是冒号**） | `openai-responses %d: %s` | SDK 形态 `POST "...": 400 Bad Request ... {body}`（**天然含 " 400 "**） | — |

**anthropic 自动续写**：`stop_reason=="max_tokens"` 时把本轮内容（含半截 JSON 的 tool_use input）作 assistant 追加重发，最多 8 轮；tool_use 按 ID 去重（后轮完整 input 覆盖）；耗尽仍截断则**丢弃全部 tool_use**（防半截 JSON 写残文件）；本轮无 content 块提前跳出（防 400）。

## 7.5 重试层与备胎链

- **retryProvider**：3 次尝试（含首次）、500ms 起 ×2 封顶 2s；成功条件 `err==nil && resp!=nil && resp.Message!=nil`（空响应构造错误）；`isNonRetryableErr` = `IsImageInputUnsupported` 优先，再匹配 `" 400 " / " 401 " / ... / invalid_request_error / authentication_error / permission_error / not_found_error`（408/429 可重试）；非重试错误若 provider 实现 `maxTokensClamper` 先自愈（**仅 anthropic 实现**：从错误串正则取上限并 atomic 钳制）。**流式：只有未 yield 任何增量时才允许重试**。
- **fallbackProvider**：每调用从主档 i=0 重试（主模型恢复即自动回主）；首 chunk 前失败可降级，已产出 chunk 的错误直透传（防重复输出）；档位**构造失败永久标记不可用**；`ctx.Err()!=nil` 立即返回。
- **三层重试叠加**：middleware RetryLLM（agent 层）→ provider retryProvider（3 次）→ retryGenerate（轻量链 3 次）——单次失败最大等待成倍增长。

## 7.6 运行时切换（角色级/实例级）与热更新

**SwitchModel（角色级，持久）**（factory.go:956-1005）：switchMu 串行 → isSwitchableRole（meta/domain/lightweight + fixed）→ registry reload 检查 → 条目存在 → **同绑定短路**（不重复探测）→ SwitchableFor 白名单 → 生效配置 → **探活（MaxTokens=1 + 60s，fail-closed：失败保持原模型）** → `registry.SetBinding` 落盘 → `invalidateChangedClients`。生效语义：下一个 LLM 客户端获取点生效（domain/叶子下次派发、lightweight 下次调用、meta 下一会话），进行中任务不中断。

**SetAgentModel（实例级，内存）**（:374-424）：只进 `agentOverrides`，**不写 role_bindings、不落盘、不失效角色缓存**；校验序同 SwitchModel（同覆盖短路）；探活 60s。回收 `ClearAgentModel`（节点死亡/取消/槽销毁；**暂停路径不得调用**）。

**热更新（models.json mtime）**：`checkRegistryReload` → `MaybeReload`（mtime+size 未变跳过；损坏**保留旧数据**静默）→ changed 则 `invalidateByRecomputeLocked`（按 roleID 重算 + 套回 thinkingOverride 后整体比对新旧 cfg，不等即删）。

## 7.7 探活与预热、轻量调用

- `VerifyConnectivity`：候选角色 = meta/domain/lightweight + 全部 fixed；按 `Provider\x00Model\x00APIKey\x00BaseURL` 去重；每后端 MaxTokens=1 临时 client + 150s 窗口（单次 30s ×3）；有任一失败 → 聚合错误（**严格启动**）。
- `WarmUp`：meta→domain→lightweight 依序构造。
- `CallLightweightWithRetry`：GetLightweightModel → `retryStreamGenerate`（**流式优先**，非流式回退；3 次、退避 500ms×2 封顶 2s、4xx 立即返回；空文本报错）→ `logLightweightCall`（`Meta: {"layer":"lightweight"}` 写 session_logs；token 为估算值无真实 usage；模型名取 LightweightResolution）。

## 7.8 middleware 链

`Chain[C].Use(mw).Use(mw).Then(final)`（从后往前包裹）。

- `RetryLLM(retries, backoff, shouldRetry)`：attempts=retries+1；每轮开始**清空 c.Resp**；空响应不重试；backoff<=0 用 100ms 翻倍**无上限**。
- `CallLLM(timeout)`：WithTimeout 包装。
- `TerminalCall`：调 `c.Call`（= agent.generateOnce）。
- 生产唯一调用点：react_agent.go:1275-1280，`shouldRetry` 传 agent 的 `shouldRetryLLMCall`（含图片不支持快速失败）——**默认 shouldRetryLLM 不含该判定，必须显式传**。

## 7.9 配置项与常量

models.json：`{models[], role_bindings{roleID:{model_id, thinking, fallback[]}}}`；`${ENV}` 展开 model/api_key/base_url；校验不校验 model_id 悬空（解析期 fail-open）；**Save 原子写**（Windows 分支先 Remove 再 Rename）。

常量：thinkingCacheKeySep `\x1f`；探活 150s/30s×3、切换 60s；providerMaxRetries 3、退避 500ms×2 封顶 2s；anthropic maxContinueRounds 8、thinkingMaxRunes 4000；responsesMinMaxOutputTokens 16；openai HTTP 超时 600s；默认端点（openai `https://api.openai.com/v1` / anthropic 官方 / ollama localhost:11434）；SSE scanner 64KB/8MB。

## 7.10 隐含约定与坑

1. **`SetBinding` 会清空同角色 fallback 链**（整体覆盖未携带原 Fallback）——注释声称"换主模型不影响备胎链"与实现矛盾。
2. **组合键必须靠 `cachedClient.roleID` 反解**；新增缓存写入路径必须同时填 roleID。
3. **`checkRegistryReload` 缓存命中路径也 stat**（每轮 LLM 调用前的 providerFn 会有锁竞争）。
4. **注册表损坏静默降级**（运行时保留旧数据；只有启动期 fail-fast）。
5. **ModelRef 缺失硬错、binding 目标缺失软错**（刻意的严格度分层）。
6. **`SetRegistry` 无锁**（约定只在启动期调一次）。
7. **applyModelEntry 无条件覆盖**（条目是权威连接参数不是增量补丁）。
8. **thinking 组合键下同角色多份 provider 各自持连接池**（无淘汰上限）。
9. **finish_reason=length 一律丢 tool_calls**（四 provider 一致；改前先想"半截 JSON 谁兜"）。
10. **reasoning_content 双向契约**（openai-chat）；responses 刻意不回传。
11. **ollama 三塌缩**（假流式/无 thinking/tool 无 ID 文本拼接）。
12. **错误串形态决定重试判定**：`" 400 "` 带空格才命中；openai 系自拼 `400:` 只能靠 body 类型串；非标准 type 的 400 会白试 2 次（唯一例外=IsImageInputUnsupported）。
13. **maxTokensClamper 只在 4xx 分支触发且仅 anthropic 实现**。
14. **流式快照语义**：chat/responses 每事件 yield 累积快照——消费者必须取最后一个非 nil 消息。
15. **retryProvider.Generate 有 (nil,nil) 窄缝**：err=context.Canceled 但传入 ctx 未取消时返回 (nil,nil)，上层会当成功空文本（触发面窄，潜在缺陷）。
16. **备胎链与实例覆盖不叠加**：set_agent_model 过的实例不走 fallback。
17. **`fallbackProvider` 未实现 ModelName()** → 配了 fallback 的角色 `llmModelName()` 为空：session_logs.model 空、`image_capability` 的 markModelNoImage 收空串 no-op → **图片降级失效**（若配 fallback 需注意；retryProvider/BladesClient 有 ModelName，唯独 fallback 层漏了）。
18. **models.json Save 的 Windows 分支非原子**（Remove 后 Rename 有窗口）。
19. **`SetBinding` 的 modelID=="" 表示删除绑定**；AppliedAt 记 UTC。
20. **LLMCallTracker 是全仓遗留件**（CallWithTimeout/slowMode/LayerStats 无生产调用）；但 retryGenerate/retryStreamGenerate/EstimateTokens 仍被轻量链复用——删文件要拆分。
21. **`EstimateTokens` 基于 nonAscii+ascii/4 粗估**（与真实 usage 无关）。
22. **中间件包注释引用了不存在的 toolchain.go**；`RetryLLM` 的 retries 是"额外重试次数"。
