## 10.2 PostgreSQL 表结构（逐表）

### session_history（会话历史，002+006+008+009 最终形态）

列：`id BIGSERIAL PK`、`session_id VARCHAR(64) NOT NULL`、`goal TEXT`、`summary TEXT`、`tool_results JSONB DEFAULT '[]'`、`meta_memory JSONB DEFAULT '[]'`（**gear/thinking 随此列落库**，006 加列）、`work_dir TEXT DEFAULT ''`（008）、`status VARCHAR(32) DEFAULT 'completed'`（009）、`created_at TIMESTAMPTZ`。
索引：`created_at DESC`；**`uniq_session_history_session_id` 唯一索引**（009 建，先按 id 保留最新去重再建，顺序不可颠倒）——`SaveHistory` 的 `ON CONFLICT (session_id)` 依赖它。

### session_events（UI 进度事件流）

列：id/session_id/type/agent/message/kind/tool/tool_path/tool_output/tool_error/success/timestamp/prompt（写入侧 2048 rune 截断）/input_tokens/output_tokens/**detail_json TEXT**。索引 `(session_id, timestamp)`。
**无 cache token 列**（对比 logger 侧有，见坑）。

### session_logs（结构化 Agent IO 日志）

列：id/session_id/agent/level/phase/message/prompt/response/input_tokens/output_tokens/model/latency_ms/created_at/meta_json JSONB。
索引：session_id / agent / level / created_at。
口径：`LLMCall` 拆成**两条**行 `phase=llm_input`（只填 prompt）与 `llm_output`（只填 response）；效率查询用 `phase LIKE 'llm%'`。

### global_knowledge（全局知识库 / 块记忆 / 领域档案，pgvector）

列：id/knowledge_type（playbook/postmortem/rule/**block_memory**/**external_kb**/**domain_profile**/domain_archive 遗留）/topic_id/content/**embedding VECTOR(1024)**（schema.go 权威；迁移文件写 768——见坑）/meta JSONB/access_count/last_accessed/created_at/**archived BOOL**（软归档，查询层全局排除）/**content_tsv tsvector 生成列**（`to_tsvector('simple', content)` STORED）。
索引：type/topic/(last_accessed,access_count)/archived/`(meta->>'domain')` btree/content_tsv GIN/**ivfflat vector_cosine_ops lists=100**。
meta 关键键：domain/session_id/parent_id/task_domain/sub_agent_id/reuse_count/source/display_name/aliases[]/files[]/subproject 等。

### learned_skills / evolution_log

- `learned_skills`：`name TEXT PK`（小写连字符=SKILL.md 主干）/title/when_to_use/content_path/embedding VECTOR(1024)（**可 NULL**）/enabled BOOL/use_count/source_session/outcome(success|failed|mixed)/created_at/updated_at。索引 ivfflat + updated_at DESC。
- `evolution_log`：id/kind(user_pref|project_lesson|skill_create|skill_update)/target/summary/source_session/created_at。

### 仅 Go DDL 的表（**无 .sql 迁移**，只跑 make migrate 不会有这些表）

| 表 | 用途 | 要点 |
|---|---|---|
| `agent_events` | 记忆流水线事件（tool_call/answer/**mailbox**） | session_id 从 agentID 派生；索引 `(agent_id, occurred DESC)` |
| `agent_messages` | 完整 ReAct 消息历史（编排页对话视图 PG 权威源） | seq 0 基下标；**delete-then-insert 全量覆盖** |
| `agent_compress_states` | 层级压缩金字塔状态 | agent_id PK，state JSONB（bundles + tail_start） |
| `agent_tree_nodes` | Agent 树节点持久化 | PK (session_id, node_id)；finished NULL=未完成 |
| `dag_jobs` | DAG 调度 | tasks JSONB |

### legacy / 兼容表

`agent_private_memory`、`agent_snapshots`（**dormant**）、`topics`、`topic_archives`（embedding + ivfflat）、`agent_registry`、`decision_logs`、`memory_write_failures`（**已弃用**，表保留避免丢历史）。

### 向量维度双源冲突（重要）

- `migrations/001_init.sql`：`VECTOR(768)`；运行时 `schema.go`：`VECTOR(1024)`（config 1024，bge-m3）。
- 只跑 `make migrate` 建库再启动 → `CREATE TABLE IF NOT EXISTS` 空操作 → 列停留 768 → `ValidateEmbeddingDimension` 比对 1024 **不一致 → bootstrap fatal**。修复路径：DROP 表后重启自动建。
- 维度校验只覆盖 global_knowledge；learned_skills/topic_archives 未纳校验。

## 10.3 Redis key 命名空间

| Key | 用途 | 结构 | TTL | 上限 |
|---|---|---|---|---|
| `topic:{id}:meta` / `:constraints` | 话题元数据/约束 | Hash | 无（可整体设） | 无 |
| `topic:{id}:deps_graph` | 依赖图 | String(JSON) | 永久 | 无 |
| `topic:{id}:events` | 事件流 | Stream（单字段 data=JSON） | 默认永久 | **无 MAXLEN、无 TTL**，只增不减 |
| `topic:{id}:decisions` | 决策日志 | List（LPush 头插） | 同上 | 无 |
| `topic:{id}:outputs:{agentID}` | Agent 产物版本 | Sorted Set（score=version） | 同上 | 无 |
| `topic:{id}:archived` | 归档摘要文本 | String | 同上 | — |
| `snapshot:{agentID}:{topicID}` | Agent 快照热缓存 | String(JSON) | **7×24h**（config snapshot_ttl_days 未接通） | 单 key |
| `sess:{sid}:agent:{aid}:msgs` | Agent 消息热层 | List（RPUSH） | **24h，每次 Append 重置** | **500 条**（LTRIM -500 -1） |

要点：

- key 派生：`agentMsgKey` 的 sid 取 agentID 的 `/` 前段；`topicKey(id, suffix)`；没有 `/` 的裸 agentID 会生成"伪 session" key（无校验）。
- **`sess:...:msgs` 不在 `topic:` 命名空间内**——`SetTopicTTLDuration`/`DeleteTopic` 的 SCAN 不会碰它，只靠自身 24h TTL。
- `ClearMsg` 只在复活重跑前显式调用（防 seq 重叠使增量游标失效）。
- `eventCursors` 进程内游标、不持久化：重启后 XRead 从 `"0"` 全量重读（依赖 Pending 幂等）。

## 10.4 启动序与写入管线

**启动**（bootstrap.go:145-190）：`NewPostgresStore`（5s Ping，**硬编码连接池 20/10/1h**，config 的 max_open_conns 是死配置）→ SetEmbeddingDim → embed.NewEmbedder → **ensureSchemas**（10 个 Ensure 幂等 DDL + 维度校验，任一失败 fatal）→ `NewRedisStore`（Ping 失败即 fatal）→ logger → SetLogger。

**会话历史写**（`SaveHistory`）：nil 补空数组 → `sanitizeJSONValue` 递归剥 NUL → `INSERT ... ON CONFLICT (session_id) DO UPDATE`。

**事件写管线**：`addEvent*`（内存 append，>500 裁到 200）→ 每轮 `persistEvents` 快照 → Prompt 截 2048 + sanitizeUTF8 → 5s 超时 → `SaveEvents` **事务内 delete-then-insert 全量覆盖**（重启续跑不叠加）、失败只记日志；`stillLive` 守卫防"删除后落库复活"。

**消息历史**：Redis 热层逐条 RPUSH（best-effort 2s）+ 终态 PG 全量覆盖（delete-then-insert）；读侧合并：`after_seq>0` 且热层有数据时只用热层；不足时热层同 seq 覆盖 PG；热层整段丢失回退纯 PG。

**块记忆**：写 `Embed(content)` → `SaveKnowledge`（pgVector 文本传参）；检索 `SearchBlockMemoryByGoal`（session 内 + 0.4 距离阈值）、`SearchBlockMemoryCrossSession`（排除当前 session + 0.5 更严阈值）、黑板 `Query`（scope 确定性：query 空=纯过滤省 embed；非空=cosine 0.4 + 距离排序）；`BumpReuse` jsonb_set 就地 +1。

**领域档案**：`UpsertDomainProfile` 查最新行 → 无行 INSERT（指纹 embed 失败降级空向量）→ 有行 files/aliases 并集、display/subproject 非空覆盖、Summary 非空才覆盖 content、Fingerprint 非空才重算 embedding。

**技能库**：`Upsert` **空向量写 NULL**（pgvector 不接受 "[]"）；`SearchSkills` fail-open；`UpdateMeta/SetEnabled` 0 行 → sql.ErrNoRows。

**效率聚合**（纯读）：角色 token/延迟 P50/P95（`percentile_cont`）、实例事件统计（tool_call/answer 计数 + WriteFile/EditFile 路径正则提取）、逐轮下钻（input/output LEFT 2000 截断）。

**邮件留痕**：`QueryAgentMailboxTrace` 按 occurred DESC LIMIT 后**内存反转回升序**（ASC 取会永远停在会话开头旧邮件）；写侧 bootstrap mailbox `WithTrace` **独立 goroutine** 异步双写（From=user/dispatcher 不写发送方行）。

**导出**：`ExportSessionData` 纯读四类数据（tool_calls 以 json.RawMessage 原样带出）。

## 10.5 降级与容错

- **启动期零降级**：PG/Redis Ping 失败即 boot 失败。
- **运行期 Redis 挂**：消息热层全 no-op（nil 安全）；写侧 2s 超时失败仅日志；读侧回退 PG。
- **运行期 PG 挂**：知识域方法全静默返回零值（nil 接收者/nil db 契约，测试固化）；DAG `checkReady` 返回哨兵错误非 panic；Agent 树返回错误（调用方 best-effort）；会话事件/历史写失败仅日志不阻塞会话；单行扫描/反序列化失败**跳过该行**。
- **内容级容错**：`sanitizeUTF8`（剥 `\x00` + ToValidUTF8；合法串零拷贝）+ `sanitizeJSONValue`（递归含 map 键）兜底 PG 22021。

## 10.6 日志链路（logger/logoutput）

- 装配：zerolog（console 四字级别标签 / json），store 非 nil 时 `NewBatchingLogStore(store, 4 workers, 1024 队列)`。
- `With/WithSession/WithAgent/WithPhase` 派生新 Logger（共享同一 batch）。
- `LLMCall` → 两条 `llmEvent`（llm_input/llm_output）；**所有落库分支要求 `fields["session_id"]` 非空**——没 WithSession 的只出 console。
- `Event(phase,message,meta)`；`Error` 附带栈（stackEnabled）。
- worker：每次 `WithTimeout(3s)` 调 `SaveSessionLog`，**失败直接丢弃**（无重试无死信）；`Close → batch.Stop`（关门→drain→wg.Wait）——不 Close 则队列尾部日志丢。
- ctx 传递：`logger.NewContext/FromContext`（轻量 LLM 调用链靠它写 session_logs）。
- 文件：`logoutput.NewWriter` 按日轮转 `logs/<entry>/YYYY-MM-DD.log`（跨天关闭重开；写入空串触发一次建文件让权限问题早暴露）；`logging.Init(entry, dir, silent)` 组合 stderr；`CleanOldLogs` 按 mtime 删超期 + 删空目录。

## 10.7 数据生命周期

`bootstrap/lifecycle.go`：**唯一自启 ticker**——启动即跑 + 每 24h：`ArchiveStale`（knowledge_archive_days，0=关；archive=置 archived=true 冷备份，查询层枚举）+ `CleanOldLogs`（默认 30 天）+ `cleanOldToolOutputs`（`.bma/tool_outputs` 默认 14 天）+ **onDaily 回调**（2026-09-16 起承接经验技能库整理 C，异步执行不阻塞）。

## 10.8 隐含约定与坑

1. **pgVector 空向量返回 `"[]"`，pgvector 定维列不接受**——learned_skills 反向写 NULL；knowledge/domain_profile 路径无守卫（domain_profile best-effort 仅日志）。
2. **注释与算子不一致**：Search 注释写"L2"，实际用 `< = >`（余弦），与 `vector_cosine_ops` 索引一致；"score=1-distance" 按余弦理解。
3. **向量维度双源**（1024 权威 vs 迁移 768）→ 只 migrate 不启服务会 fatal。
4. **5 张表无 SQL 迁移**（agent_events/agent_messages/agent_compress_states/agent_tree_nodes/dag_jobs），靠服务启动自举。
5. **session_events 无 cache token 列**：logger 侧 CacheHit/Miss 在 `toStoreRecord` 被丢弃 → 缓存命中率**无法从 DB 聚合**。
6. **LLM 日志行 level 为空串**（llmEvent 不设 Level，显式传 ''）→ 按 level=info 过滤会漏全部 llm_input/output 行。
7. **日志批量写失败静默丢弃**；Close 必须先于 pgStore.Close。
8. **`SetLogger` 不传播给 LearnedSkills**（只注入 Session/Knowledge）→ 其扫描失败日志不产出。
9. **PostgresStore/RedisStore 硬编码连接池**：config 的 max_open/max_idle/conn_max_lifetime/pool_size/read_timeout 等全是死配置。
10. **`sess:` 与 `topic:` 不同源**：sess 的 session 段从 agentID 派生、topic 用 topicID；排查别混。
11. **Stream 无 MAXLEN 无 TTL**：话题事件流只增不减；`eventCursors` 仅进程内。
12. **`SaveEvents` 每轮全量重写**（delete-then-insert），事件多时事务重；内存侧 >500 裁 200 是实际上界。
13. **会话硬删不删块记忆**（global_knowledge 按 session_id 的沉淀仍在，跨会话外脑语义）。
14. **写库前双重 sanitize**（agent 侧 + 存储层）；扫描失败静默 continue 无错误计数。
15. **`topic_archives.SaveTopicArchive` 的 outputs/decisions/embedding 参数被忽略**（只存 summary）。
16. **表全无 owner 列**（多租户预留缺口，与项目 owner 约定相比尚未落地）。
