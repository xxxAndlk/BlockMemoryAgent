# BlockMemoryAgent 执行流程详解

> 本文以「在 Dashboard 输入框输入一条目标并点击 Run」为起点，完整追踪一条命令从浏览器到磁盘落盘、再到前端 SSE 回显的全过程。每一步标注到**方法 + 文件**。
> 适合对照源码理解 Graph 状态机调度、Skill 装配、工具调用防幻觉、事件回流与 SSE 实时回显。

---

## 阶段 0：前端发起请求

**`web/src/views/dashboard/index.vue`**
1. `runSession()` —— 校验 `goal.value` 非空，`loading=true`
2. 调 `createSession(goal.value.trim())`

**`web/src/api/session.ts`**
3. `createSession(goal)` → `fetchJson('/sessions', { method:'POST', body:{goal} })` → `POST /api/sessions`

---

## 阶段 1：HTTP 入口与会话创建

**`backend/main.go`**
4. `mux.HandleFunc("/api/sessions", ...)` 匹配 POST → `sessionMgr.HandleCreateSession(w, r)`

**`backend/internal/server/session.go`**
5. `HandleCreateSession` —— 解析 body `{goal}`，校验非空 → `m.CreateSession(ctx, goal)`
6. `CreateSession(ctx, goal)`:
   - `sessionID = fmt.Sprintf("session-%d", m.seq.Add(1))`
   - 构造 `Session{Status:"running", Events:[], Messages:[{system, Goal}]}`，存入 `m.sessions`
   - **`go m.runSession(ctx, session)`** 异步执行，立即返回 session 给前端
7. 前端拿到 `s.id` → `viewSession(s.id)` 跳转 `/session?id=...`，并调 `load()` 刷新列表

---

## 阶段 2：会话执行（Graph 主循环）

**`session.go` `runSession(ctx, session)`**
8. `ctx, cancel = context.WithTimeout(ctx, 5*time.Minute)`
9. `state = types.NewThreeLayerState(session.ID)`；`state.DomainGoal = session.Goal`
10. `m.addEvent(session, "system", "MetaAgent", "会话启动，目标: ...")`
11. `result, err = m.graph.Invoke(ctx, state)` ← 进入 Graph

**`backend/internal/graph/three_layer_graph.go` `ThreeLayerGraph.Invoke`**
12. `ctx = WithSessionID(ctx, state.SessionID)`（把会话 ID 注入 context，供事件路由用）
13. `current = "MetaAgent"`，进入 `for` 循环（上限 200 步）
14. `node = g.nodes["MetaAgent"]` → `MetaAgentNode`
15. `newState, err = node.Invoke(ctx, state)` —— 调用 MetaAgent

---

## 阶段 3：MetaAgent 首轮——领域分析

**`backend/internal/graph/meta_agent.go` `MetaAgentNode.Invoke`**
16. `n.stepCount++`；`n.runWatchdog(ctx, state)`（每轮跑看门狗）
17. `n.processMailbox(state)`（每轮拉广播邮件）
18. `len(state.ActiveBlocks)==0 && CurrentBlockID==""` → `return n.handleInitial(ctx, state)`

**`handleInitial(ctx, state)`**
19. `n.emit(ctx, "think", "分析用户目标，决定是否需要拆分领域")`
20. `historySection = n.loadHistorySection(ctx)`（读 `session_history` 最近 5 条注入 prompt，支持"上次/那个文件"指代）
21. `n.isSimpleQuestion(state.DomainGoal)` 判断：
    - 命中寒暄模式且无指代词 → `n.callLLM(...)` 直接答，`ActionFinish` 短路返回
    - 否则继续走 Graph
22. `domains = n.analyzeDomains(ctx, state)`

**`analyzeDomains(ctx, state)`**
23. `n.callLLM(ctx, 领域分析prompt)` —— `callLLMAs`：
    - `modelFactory.GetMetaModel(ctx)` 取轻量模型
    - `n.rt.Soul.Inject(prompt)` 注入人格
    - `n.emitDetail(ctx, "prompt", ...)` 推 prompt 调试事件
    - 路由温度 0：`soul.Temperature(KindRouting, 0)` → `temperatureWrappedLLM`
    - `n.llmTracker.CallWithTimeout(...)` 调 LLM
    - `n.emitDetail(ctx, "token_usage", ...)` 推 token 事件
24. `n.parseDomainsFromLLM(resp)` 解析 `[{"name","goal"}]`；失败回退 `analyzeDomainsByRules(goal)`

**回到 `handleInitial`**
25. TaskBoard 初始化：`n.rt.Boards.GetOrCreate(sessionID, goal)`，每个领域 `bd.AddSubTask(name+" - "+goal)`
26. 对每个领域：
    - `n.factory.CreateDomainAgent(ctx, sessionID, domain.Name, domain.Goal, "")`（`role_factory.go`，可能调 LLM 生成角色定义并注册到 RoleRegistry）
    - `n.emitDetail(ctx, "agent_created", ...)`
    - 构造 `SessionBlock{ID, Domain, Goal, Agents:[inst.ID], TaskResults:map}` 存入 `state.ActiveBlocks`
27. 选第一个 block：`state.CurrentBlockID=blockID`；`state.TargetRoleID=block.Agents[0]`；`state.NextAction=ActionSwitch`
28. `n.updateSessionSummary(state)` 返回

---

## 阶段 4：Graph 调度切换到 DomainAgent

**回到 `three_layer_graph.go` `Invoke` 循环**
29. `next = g.determineNext("MetaAgent", state)` → `metaAgentNext(state)`：`ActionSwitch` 且 `TargetRoleID!=""` → 返回该 DomainAgent 实例 ID
30. `current = next`（实例 ID）
31. 下一轮：`g.nodes[instID]` 不存在 → `g.resolveInstanceNode(instID)`：
    - `registry.GetInstance(instID)` → `inst.Type==RoleTypeDomain` → `NewDomainAgentNode(instID, registry, factory)`
    - `g.injectModelFactory(node)`（注入 ModelFactory/Runtime/ToolCallback）
    - `g.injectProgress(node)`（注入 ProgressCallback）
    - 存入 `g.nodes[instID]`
32. `node.Invoke(ctx, state)` —— 调用 DomainAgent

---

## 阶段 5：DomainAgent——任务拆解与 Skill 装配

**`backend/internal/graph/domain_agent.go` `DomainAgentNode.Invoke`**
33. `inst = n.registry.GetInstance(n.instID)`；`UpdateInstanceStatus(Active)`
34. `n.ensureSkillSet(ctx, inst, state)`

**`ensureSkillSet`（`domain_agent.go`）**
35. `n.rt.Skills.GetForAgent(n.instID)` 已有则跳过
36. 否则 `modelFactory.GetDomainModel(ctx)` 取 LLM
37. `n.rt.Skills.Pool().AssembleSet(ctx, llm, instID, domain, goal, 8)`（`skill/pool.go`）：
    - `FilterByDomain(domain)` 规则预筛
    - 候选 ≤8 直接返回；否则 `llmPickSkills` 让 LLM 选 8 个
38. `n.rt.Skills.Bind(set)` 绑定到该 Agent 实例

**`analyzeTasks(ctx, state)`（`domain_agent.go`）**
39. `n.callLLM(ctx, 任务拆解prompt)` → `parseTaskListFromResp(resp)` 拆出 2-4 个子任务；失败回退 `analyzeTasksByRules`
40. `shouldSplitToSubDomains` 判断是否再细分（可选 Layer 2.5，跳过此处常见路径）
41. 过滤已完成任务得 `pendingTasks`
42. `results = n.dispatchAssistantsParallel(ctx, state, inst, pendingTasks)`

**`dispatchAssistantsParallel`（`domain_agent.go`）**
43. 对每个 task：
    - `createAssistantForTask` → `matchFixedAssistant(task)`（按 keywords/skills 评分匹配固定助手），无匹配则 `factory.CreateAssistant(...)` 动态生成
    - `go func(...) { n.runAssistant(ctx, state, aInst, aDef, task) }`（goroutine 并行）
    - `wg.Wait()`

---

## 阶段 6：Assistant 执行——LLM + 工具循环

**`runAssistant`（`domain_agent.go`）**
44. `UpdateInstanceStatus(Active)`
45. `retryWithBackoff(3, 100ms, func() { result, err = n.executeAssistantTask(ctx, def, task, state) })`

**`executeAssistantTask`（`domain_agent.go`）**
46. `executor = NewToolExecutor("")`；`executor.SetCallback(n.toolCallback)`（← 关键：工具结果回调 = SessionManager.handleToolResult）
47. `skillBrief = n.rt.Skills.GetForAgent(n.instID).PromptList()`（取装配的 Skill 列表）
48. `executeAssistantWithTools(ctx, modelFactory, executor, def, task, state, skillBrief, n.progress, "助手[...]")`

**`executeAssistantWithTools`（`llm_tools.go`）**
49. `modelFactory.GetModel(ctx, roleDef.ID)` 取 LLM
50. `ctx, cancel = WithTimeout(ctx, 60s)`
51. → `executeWithTools(ctx, llm, executor, roleDef, task, state, skillBrief, progress, agentName)`

**`executeWithTools`（`llm_tools.go`，核心 8 轮循环）**
52. `sessionID = state.SessionID`
53. `skillSection = mergeToolList(skillBrief, defaultTools)`（Skill 子集前置 + 默认工具兜底，按 ToolRef 去重）
54. 拼 `systemPrompt`（含 skillSection + osHint + 硬性规则：写文件必须调 WriteFile）
55. **for round := 0; round < 8; round++:**
    - `emit(ctx, "llm", "第 N 轮：调用 LLM 决策...")`
    - `emitDetail(ctx, "prompt", ...)` / `emitDetail(ctx, "token_usage", ...)`
    - `resp, err = llm.Generate(ctx, prompt)`
    - `toolReq = parseToolCall(resp)`：
      - **nil（不是工具调用）**：
        - `claimsFileWrite(resp) && !alreadyWritten` → 幻觉检测，强制再逼一次 WriteFile
        - `taskRequiresWriteFile(task) && !alreadyWritten` → 完成门控，拒绝文字答案，强制 WriteFile
        - 否则视为最终答案返回
      - **非 nil（工具调用）**：
        - `emitDetail(ctx, "tool_call", "调用工具 X", argsStr)`
        - **`result = executor.Execute(WithSessionID(ctx, sessionID), toolReq.Tool, toolReq.Args)`** ← 实际执行
        - 成功：`consecutiveFailures=0`，`emitDetail(ctx, "tool_result", ...)`
        - 失败：`consecutiveFailures++`，`emit(ctx, "error", ...)`；连续 ≥3 次放弃

---

## 阶段 7：工具真正落盘

**`backend/internal/graph/tool_executor.go` `ToolExecutor.Execute`**
56. `toolName = normalizeToolName(toolName)`（`write_file`→`WriteFile`）
57. `sessionID = SessionIDFromContext(ctx)`
58. `switch toolName` → `e.writeFile(args)`：
    - `absPath = e.resolvePath(path)`
    - `os.MkdirAll(dir, 0755)`
    - `os.WriteFile(absPath, []byte(content), 0644)` ← **磁盘落盘**
    - 返回 `&ToolResult{Tool:"WriteFile", Success:true, Output:"wrote N bytes", Path:absPath}`
59. `result.SessionID = sessionID`
60. `e.callback != nil` → **`e.callback(result)`** = `SessionManager.handleToolResult(result)`

---

## 阶段 8：事件回流到会话（两条回调通道）

### 通道 A：工具结果回调
**`session.go` `handleToolResult(result)`**
61. `m.mu.RLock()` 收集 `Status=="running"` 且 `session.ID==result.SessionID` 的会话
62. `m.addEvent(session, "tool_exec", "ToolExecutor", "执行工具: WriteFile", "", result.Tool, result.Path, result.Output, "", result.Success)`

### 通道 B：进度回调（think/llm/tool_call/token_usage 等）
Graph 各节点 `emit/emitDetail` → `n.progress(ctx, ProgressEvent{...})` = `SessionManager.handleProgress`
**`session.go` `handleProgress(ctx, ev)`**
63. 拼 `msg`（含 detail 截断 500 字）；提取 `prompt`/`inputTokens`/`outputTokens`
64. 按 `ev.SessionID` 精确匹配运行中会话
65. `m.addEventDebug(session, "progress", ev.Agent, msg, ev.Kind, ..., prompt, in, out, detail)`

**`addEventDebug`**
66. 构造 `SessionEvent{...Timestamp:time.Now()}`，`m.mu.Lock()` → `session.Events = append(...)` → unlock
67. `log.Printf("[%s] %s: %s", ...)`（日志）

---

## 阶段 9：DomainAgent 汇总 → MetaAgent 收尾

**回到 `dispatchAssistantsParallel` 之后（`domain_agent.go` `Invoke`）**
68. `block.TaskResults[task] = result`（写入会话块）
69. `n.summarizeResults(state)`；`UpdateInstanceStatus(Done)`；`block.Status="completed"`；`ActionContinue`

**Graph `Invoke` 循环**
70. `determineNext` → `domainAgentNext`：`ActionContinue && !IsCalling()` → 返回 `"MetaAgent"`

**MetaAgent 再次 Invoke**
71. `runWatchdog` + `processMailbox`
72. `CurrentBlockID != "" && !IsCalling()` → `switchToNextBlock(ctx, state)`：
    - `collectBlockResult` 汇总当前 block 到 `state.SessionSummary`
    - `state.CompletedBlocks = append(...)`；`delete(ActiveBlocks, CurrentBlockID)`
    - 还有活跃 block → 切下一个；否则 `finalizeSession`
73. `finalizeSession(ctx, state)`：`callLLM` 生成最终回答
74. `ActionFinish` → `determineNext` → `"Sinker"` → `sinkerNode.Invoke` 强制 `ActionFinish`
75. `Invoke` 检测 `ActionFinish` → `return state, nil`

---

## 阶段 10：会话收尾与持久化

**`session.go` `runSession` 返回后**
76. `m.mu.Lock()`：`session.Status="completed"`；`session.Result=result.SessionSummary`；`session.State=result`；`EndedAt=now`
77. 遍历 `registry.GetInstancesBySession` 加 `agent_done` 事件
78. `addEvent "会话完成: ..."`
79. `m.persistHistory(session)`：过滤 `tool_exec` 事件 → `pgStore.SaveSessionHistory`（落 `session_history` 表）
80. `ma.TimeoutStats()` + `LLMTracker().TokenTotals()` → 加 `stats` 事件

---

## 阶段 11：前端 SSE 实时回显

**`web/src/views/session/index.vue` `selectSession` → `startStream`**
81. `streamSession(s.id, onEvent, onDone, onError)` → `new EventSource('/api/sessions/{id}/stream')`

**`session.go` `HandleSessionStream`**
82. 设 SSE headers；`data, _ = json.Marshal(session)` 推首条完整快照；`flusher.Flush()`
83. `ticker = 500ms`；`lastEventCount = len(session.Events)`
84. 循环：
    - `len(session.Events) > lastEventCount` → 逐条 `json.Marshal(ev)` → `data: {...}\n\n` → flush
    - `lastEventCount = len(session.Events)`
    - `session.Status != "running"` → 推 `{type:"done"}` → return

**前端 `onEvent` 回调（`session/index.vue`）**
85. 过滤首条全量快照（含 `id/goal/events` 字段的对象）
86. `s.events.push(ev)` → `ExecutionLog.vue` 渲染（时间/Agent/kind badge/markdown/工具详情折叠）

## 完整方法调用链（精简版）

```
[前端] dashboard.runSession
  → api.createSession ──POST /api/sessions──►
[后端] main.mux → HandleCreateSession
  → CreateSession → go runSession
     → graph.Invoke(ctx, state)
        ├─ MetaAgentNode.Invoke
        │   ├─ runWatchdog / processMailbox
        │   └─ handleInitial
        │       ├─ loadHistorySection
        │       ├─ isSimpleQuestion? → callLLM 短路
        │       ├─ analyzeDomains → callLLMAs → llmTracker.CallWithTimeout
        │       ├─ Boards.GetOrCreate + AddSubTask
        │       ├─ factory.CreateDomainAgent
        │       └─ ActionSwitch → TargetRoleID=domainInst
        ├─ determineNext → metaAgentNext → 返回 instID
        ├─ resolveInstanceNode → NewDomainAgentNode + 注入
        ├─ DomainAgentNode.Invoke
        │   ├─ ensureSkillSet → Pool.AssembleSet → Registry.Bind
        │   ├─ analyzeTasks → callLLM
        │   ├─ dispatchAssistantsParallel
        │   │   └─ runAssistant → executeAssistantTask
        │   │       └─ executeAssistantWithTools → executeWithTools (8轮)
        │   │           ├─ llm.Generate
        │   │           ├─ parseToolCall
        │   │           ├─ executor.Execute(WithSessionID)
        │   │           │   └─ writeFile → os.WriteFile  ← 落盘
        │   │           │   └─ callback → handleToolResult → addEvent
        │   │           └─ emit/emitDetail → progress → handleProgress → addEventDebug
        │   └─ summarizeResults → ActionContinue
        ├─ determineNext → 回 MetaAgent
        ├─ switchToNextBlock → finalizeSession → callLLM
        └─ ActionFinish → Sinker → return
     → persistHistory → SaveSessionHistory
[SSE]  HandleSessionStream 500ms 轮询 → data: {event}\n\n
[前端] EventSource.onmessage → s.events.push → ExecutionLog 渲染
```

## 关键设计点回顾（沿这条路径）

| 机制 | 体现位置 |
|---|---|
| **会话隔离** | `WithSessionID` 在 `Invoke` 入口注入，`handleToolResult`/`handleProgress` 按 `SessionID` 精确路由事件，避免多会话串流 |
| **上下文纯净** | `ensureSkillSet` 只装配 ≤8 个 Skill，`skillBrief` 注入 system prompt，ToolExecutor 全量工具作为兜底 |
| **防幻觉** | `executeWithTools` 完成门控 + `claimsFileWrite` 幻觉检测 + 连续失败干预 |
| **记忆外部化** | `loadHistorySection` 从 `session_history` 读历史注入，主 Agent 上下文只带指针 |
| **异步协同** | `processMailbox` 每轮拉广播邮件，工具/进度事件经回调异步落 `Session.Events` |
| **降级** | 无 API Key → `mockClient`；领域分析/任务拆解失败 → 规则回退 |

## 附：状态机动作流转图

```
用户输入
   │
   ▼
MetaAgent.handleInitial ──ActionSwitch──► DomainAgent(实例)
   │                                          │
   │ (简单问题短路)                           ▼
   │ ActionFinish                       DomainAgent.Invoke
   │                                    ├─ ensureSkillSet
   │                                    ├─ analyzeTasks
   │                                    └─ dispatchAssistantsParallel
   │                                         │
   │                                         ▼
   │                                    Assistant (LLM+工具8轮)
   │                                         │
   │                                    ActionContinue
   │                                         │
   ▼◄────────────────────────────────────────┘
MetaAgent.switchToNextBlock
   ├─ 还有活跃 block → ActionSwitch → 下一个 DomainAgent
   └─ 全部完成 → finalizeSession → ActionFinish → Sinker
```

`NextAction` 取值：`Continue`（回 MetaAgent 重评估）/ `Switch`（切到 TargetRoleID）/ `Escalate`（升级仲裁）/ `Finish`（结束）。
