### 任务 78：软停止后发消息无响应修复（旧模式 Stop 不打断 MetaAgent LLM + 消息不清倒计时）

- **人物**：Claude（罗坤）
- **背景**：日志取证（tui/2026-08-20.log，session-1787207955709431700）：
  - 15:16:03 MetaAgent LLM 调用开始（ask_user 答复后续轮），glm-5.3 流式挂 7m20s 无输出。
  - 15:18:24 用户双击 ESC 软停止（旧模式，`domain_hot_resident_enabled: false`）。`Stop` 里 `cancelFn()` 只在热驻模式调用（service_react.go），**旧模式不取消 MetaAgent 在跑的 LLM 调用** -> 会话一直 Running，卡在挂死的 LLM 流上。
  - 15:18:37 用户新消息：`wasRunning=true` -> 只入队；`cancelSoftStopState` 只挂在 `!wasRunning` 分支，**倒计时不清**。
  - 15:23:24 5m 倒计时到期 -> `destroyAfterSoftStop` 硬销毁：cancel ctx 杀掉 LLM（`context canceled`），会话置 Error"软停止超时未续跑，任务已销毁"。用户视角 = 停止后发消息无任何响应。
  - 根因 = 旧模式 Stop 的设计假设 MetaAgent 总是阻塞在等子 Agent（靠 pending-children 保护落 PausedOnChild），但 MetaAgent 正在 LLM 调用中时没人打断它，新消息也不清倒计时，5 分钟后整体销毁。

#### 改动（全在 `backend/internal/agent/service_react.go`）

- **Stop 取消 MetaAgent ctx 不再限热驻**：`cancelFn()` 无条件执行（与原注释声明的意图一致）。旧模式否则 MetaAgent 卡在跑中的 LLM 上，会话长期 Running，倒计时到期即整体销毁。
- **isSoftStopCancel 去掉 hotResident 门**：软停止标记命中 + `context.Canceled` 即落暂停态而非 Error（硬取消先置 Error 终态，不误判）。
- **新增 `softStopPauseKind` 暂停分类**：旧模式下树中存在 Running/Paused domain（MetaAgent 原在等子 domain）-> 维持 PauseOnChild 原恢复路由（resumePausedDomain）；否则（LLM 被打断、无域在跑）-> PauseUserStop（awaiting_clarify，发消息走 MetaAgent 续跑）。热驻模式恒 PauseUserStop，行为不变。
- **sendMessage 无条件 `cancelSoftStopState`**：软停止窗口内任何用户消息都视作续跑意图（清倒计时 + 清标记），不再只挂在 `!wasRunning` 分支。
- **destroyAfterSoftStop 补 AwaitingClarify**：软停落 PauseUserStop 后 5m 未续跑照旧销毁，语义不漂移（普通 awaiting_clarify 无 destroyAt，不受影响）。
- **PauseUserStop 文案按模式分流**：热驻保留原"热驻保留可复用"文案；旧模式改"任务已停止。发送消息可继续任务（销毁倒计时内未续跑将销毁）"。
- **执行结果**：✅ 完成。`go build ./...` 绿；`agent`/`tui` 包 `go test` 全绿。
  - **运维动作（需用户执行）**：重启 TUI 进程加载新逻辑；此后停止后再发消息会打断挂死的 LLM 调用并续跑（或清倒计时等当前轮收尾后继续）。
