# 插件系统设计（范式定稿 v2）

> 状态：**已实现**（2026-08-16，实现偏差见文末 §9）
> 日期：2026-08-16
> 范围：热插拔插件范式 + 初始插件选型（联网搜索 / Computer Use）

---

## 1. 设计目标

- 插件**热插拔**：运行中 enable/disable，无需重启进程，对正在运行的 Agent 下一轮迭代即生效。
- 初始自带两类插件：**联网搜索** 与 **Computer Use**，均选用免费开源的 MCP 实现。
- **兼容外部插件生态**：能加载 Claude Code / Codex / OpenClaw 的插件（MCP 部分全兼容，skills 部分可移植），不强行兼容无法兼容的（DeepSeek Harness 的 Cordis 进程内插件）。

## 2. 核心决策

### 2.1 唯一执行面 = `tool.Registry`

插件本质是「一组 `tool.Tool` 的打包 + 生命周期管理」。不新建执行面，所有插件工具最终都挂进 `backend/internal/domain/tool/registry.go` 的 `Registry`。

热插拔天然成立的两个地基（已核实）：

- `react_agent.go:427`：ReAct 循环**每轮**现取 `a.tools.Schema()`，新注册的工具下一轮迭代即对 Agent 可见。
- `tool_adapter.go:71`：adapter 实时透传 `inner.Schema()`，无静态快照（角色白名单除外，见 §4.3）。

### 2.2 MCP 是外部插件的统一协议

Claude Code（`.mcp.json`）、Codex（`config.toml` 的 `[mcp_servers]`）、OpenClaw 的插件格式在 MCP 上收敛。采用官方 Go SDK `modelcontextprotocol/go-sdk`（client+server 双全，stdio / streamable HTTP / SSE）作为桥接层。

**不做** Go `.so` 动态库（不支持 Windows、跨版本易碎）。

### 2.3 Manifest 是 Claude `plugin.json` 的超集

直接兼容最大的现存插件语料（Claude/Codex 插件市场），解析成本最低。

## 3. 三种插件形态（Kind）

```go
type Kind string
const (
    KindBuiltin Kind = "builtin" // 编译进二进制的进程内 Go 插件
    KindMCP     Kind = "mcp"     // 外部 MCP server（stdio 子进程或远程 HTTP）
    KindBundle  Kind = "bundle"  // Claude/Codex 插件目录包
)
```

| Kind | 生命周期 | 热插拔方式 | 典型用途 |
|---|---|---|---|
| builtin | `Init → Start → Stop` | Registry Register/Unregister | 核心自研工具 |
| mcp | `connect → ListTools → 适配注册 → disconnect` | 拉起/杀子进程或断连 HTTP | 搜索、Computer Use 等外部插件 |
| bundle | 解析目录 → 展开为若干 mcp 插件 + skill 条目 | 目录级 enable/disable | 兼容 Claude/Codex 插件包 |

### 3.1 Plugin 接口（builtin）

```go
type Manifest struct {
    ID          string   // 唯一标识，如 "web_search"
    Name        string   // 展示名
    Version     string
    Description string
    Kind        Kind
    RequiresEnv []string // 依赖的环境变量，缺失则拒绝 enable 并给出原因
    ToolNames   []string // 声明提供的工具名
    Roles       []string // 可见角色，缺省 ["*"]
}

type Deps struct {
    Logger  *slog.Logger
    Config  map[string]any // plugins.yaml 中该插件的 settings 段
    WorkDir string
}

type Plugin interface {
    Manifest() Manifest
    Init(ctx context.Context, deps Deps) error // 校验配置、建 client，不注册工具
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
    Tools() []tool.Tool
}
```

### 3.2 MCPBridge（mcp）

- 用 go-sdk client 连接三种传输：stdio（spawn `command/args/env`）、streamable HTTP（`url`）、docker（`docker run -i --rm image`，stdio 桥接 + 停止时显式 `docker rm -f` 回收，见 §6.4）。
- `ListTools()` → 每个远端工具包装为实现 `tool.Tool` 的适配器（`Execute` 内发 `CallTool`，结果转 `*tool.Result`），注册进 `tool.Registry`。
- 连接断开/子进程退出 → 自动 Unregister，管理 API 中状态标记为 `degraded`，带退避重连。

### 3.3 Bundle 加载器（bundle）

解析插件目录：

- `.claude-plugin/plugin.json` → Manifest 元数据
- `.mcp.json` → 展开为若干 mcp kind 插件（支持 `${CLAUDE_PLUGIN_ROOT}` 路径替换）
- `skills/*/SKILL.md` → 解析 frontmatter，注入现有 `skill.Pool`
- `hooks/hooks.json` → 暂不支持（事件模型为 Claude Code 专有，后续映射到本项目 Agent 生命周期事件）

约定 `plugins.d/` 目录：外部插件目录丢进去即可被扫描，经管理 API 显式加载（不引入 fsnotify）。

## 4. 热插拔语义

### 4.1 PluginManager（`backend/internal/plugins/manager.go`）

- 注册表 `map[string]*instance`（RWMutex），instance 记录插件 + 状态。
- 状态机：`registered → initialized → running → stopped / degraded`。
- `Enable(id)`：Init → Start → 注册工具；失败回滚（已注册的工具摘除）。
- `Disable(id)`：先 Unregister 全部工具，再 Stop。

### 4.2 `tool.Registry` 并发安全改造

当前 `Register/Dispatch` 无锁，必须改：

- 加 `sync.RWMutex`：`Register` / 新增 `Unregister(name)` 用写锁；`Dispatch` / `Schema` 用读锁。
- Disable 时进行中的 Dispatch 由读锁保护自然完成；之后 LLM 再调该工具收到 "tool not found" 错误回灌，ReAct 循环可自愈。

### 4.3 角色白名单的动态可见

`toolRegistryAdapter.allowed` 是创建期快照。方案：adapter 过滤逻辑改为「静态白名单 ∪ 动态可见集」，挂一个 `pluginVisibility func(toolName string) bool` 回调，由 PluginManager 依据 Manifest 的 `Roles` 字段判定（缺省 `["*"]` 全角色可见）。

## 5. 配置与管理 API

```yaml
# config/plugins.yaml
plugins:
  web_search:
    kind: mcp
    enabled: true
    settings:
      transport: docker                        # 自托管 firecrawl 栈（本地容器，免 key）
      image: bma/firecrawl-mcp:local
      env:
        FIRECRAWL_API_URL: http://host.docker.internal:3002
        FIRECRAWL_API_KEY: ${FIRECRAWL_API_KEY:self-hosted}
      # 云端免 key 兜底：transport: http + url: https://mcp.firecrawl.dev/v2/mcp
  computer_use:
    kind: mcp
    enabled: false            # 高危插件，默认关闭，显式开启
    settings:
      transport: docker       # Xvfb 沙箱容器（bma/computer-use-mcp:local）
      image: bma/computer-use-mcp:local
      ports: ["6081:6081"]    # noVNC 观察口
      destructive: true
      # transport: stdio      # 开发机直起（操作真机，仅调试）
      # command: npx
      # args: ["-y", "@zavora-ai/computer-use-mcp"]
```

- 加载复用 `config.Load` 的同目录深合并惯例；密钥只走 `${VAR}` 环境变量插值。
- 管理 API（挂在 `bootstrap/mux.go`）：
  - `GET /api/plugins` — 列表（状态、工具清单、缺失 env 提示）
  - `GET /api/plugins/{id}`
  - `POST /api/plugins/{id}/enable` / `POST /api/plugins/{id}/disable`
  - `POST /api/plugins/reload` — 重读 plugins.yaml + 扫描 `plugins.d/`（显式触发，仿 `soul.Loader.Reload()`）

部署形态：

- **默认（docker transport 沙箱）**：`bma/computer-use-mcp:local` 镜像（`docker/computer-use/Dockerfile`：Xvfb + fluxbox + x11vnc + noVNC + `@zavora-ai/computer-use-mcp`，stdio MCP），由后端 enable 时 `docker run -i` 拉起、disable 回收；noVNC 经 `settings.ports` 映射宿主 6081 供人观察。AI 不直接操作真机。

| 生态 | 兼容性 | 方式 |

### 6.4 Docker 部署形态（2026-08-16 定稿）

插件进程全部容器化，经管理 API 热插拔（enable → 起容器/连端点，disable → 摘工具 + 回收容器）：

- **`docker` transport**（`mcpbridge/docker.go`）：`docker run -i --rm --name bma-plugin-<id> [-e K=V]... <image>`，stdio 管道桥接 MCP；停止时显式 `docker rm -f`（Windows 下 kill CLI 不转发信号，否则容器残留）；启动前 best-effort 清同名残留。只经 `-e` 显式传 `settings.env`，不继承宿主环境。
- **web_search 链路**：后端 →(docker stdio MCP)→ `bma/firecrawl-mcp:local` 容器（`docker/firecrawl-mcp/Dockerfile`，node:20-alpine 预装 firecrawl-mcp，避免 enable 时 npx 现场下载）→(REST `http://host.docker.internal:3002`)→ 本地 firecrawl 自托管栈。
- **firecrawl 自托管栈**（`docker/docker-compose.firecrawl.yml`，独立 compose project）：`api`(:3002) + `playwright-service` + `redis` + `rabbitmq` + `nuq-postgres`，全部 `ghcr.io/firecrawl/*` 预构建镜像（Docker Hub 不通时基础镜像走 daocloud 加速前缀）；`USE_DB_AUTHENTICATION=false` 免 key。启动：`docker compose -f docker/docker-compose.firecrawl.yml up -d`。
- **computer_use**：同为 docker transport stdio 沙箱（`bma/computer-use-mcp:local`，`docker/computer-use/Dockerfile`：Xvfb + noVNC + `@zavora-ai/computer-use-mcp`）；noVNC 观察口经 `settings.ports`（`6081:6081`）映射；enable/disable 即容器启停。原 compose `computer` 常驻服务已移除（computer-use-mcp 无 HTTP 模式）。
- http transport 的单次请求超时对齐 `exec_timeout_sec`（原硬编码 30s 会掐断自托管 scrape/crawl 长调用）。
