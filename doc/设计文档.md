# 多Agent协同智能体记忆管理系统设计文档

## 1. 项目背景与目标

### 1.1 问题起源
在当前的大语言模型（LLM）Agent项目中，我们面临两大核心挑战：
- **上下文窗口爆炸**：多步任务执行、工具调用、反复修改导致上下文中堆积大量无关信息，模型注意力被稀释，出现“迷失在中间”和“伪遗忘”。
- **跨模块/跨Agent协作混乱**：当多个功能模块或多个子Agent高度相关且频繁切换时，各自的推理日志交叉污染，模型难以维持清晰的任务边界和连续思考。

### 1.2 设计目标
构建一套**记忆管理中间层**，让多Agent系统具备以下能力：
- 每个Agent始终工作在**干净、聚焦、无污染**的上下文中。
- 跨Agent协作时，通过受控的**共享工作区**交换精炼信息，而非全量历史。
- 主Agent能够快速路由任务，精准分配上下文，并维持全局话题的连贯性。
- 支持话题隔离、模块上下文切换、长程记忆压缩和遗忘。

## 2. 核心设计思想

我们将记忆视为**可存储、可检索、可压缩、可遗忘的资源**，在架构上实行**三层记忆体系 + 一层编排**。

- **不把LLM上下文当作唯一记忆体**，而是作为瞬时工作记忆。
- **记忆管理由程序机械执行**，LLM仅负责基于给定上下文的推理。
- **上下文组装遵循“最小必要信息”原则**，严格按话题、模块、相关性进行裁剪。

## 3. 三层记忆体系

### 3.1 私有记忆层（Agent Private Memory）
- **存储内容**：每个Agent在本话题中的完整执行轨迹，包括每一步的推理链、工具调用及结果、中间变量、未解决问题。
- **存储形式**：结构化的情节记录（Episode），每条包含步骤ID、时间戳、动作、观察摘要、完整观察（可选）、反思、重要性标记。
- **访问权限**：仅本Agent可见，其他Agent无权直接读取。
- **生命周期**：跟随话题活跃期。当Agent被切出时，保存为**私有快照**；重新激活时，优先加载快照，恢复上下文连续性。

### 3.2 话题共享工作区（Topic Workspace）
- **定位**：跨Agent的“公共白板”，由主Agent维护。
- **存储内容**：
  - 话题ID、目标、当前状态
  - 全局约束（如单位、环境设定）
  - 各Agent公开输出摘要（含版本号、数据引用、已知问题）
  - 待处理事件（修改请求、依赖触发）
  - 决策日志
- **写入规则**：仅主Agent或经主Agent验证的Agent输出可写入；Agent必须通过`publish()`接口发布精炼的**状态对象**，禁止直接暴露内部日志。
- **读取规则**：所有参与该话题的Agent可读取，但读取时由主Agent**按依赖关系过滤**，只提供与本Agent当前任务直接相关的部分。

### 3.3 全局知识库（Global Knowledge Base）
- **存储内容**：跨话题的持久知识，如用户偏好、项目规范、历史成功案例、Agent能力注册表。
- **技术方案**：向量数据库 + 结构化元数据存储。
- **检索方式**：语义搜索、关键词匹配、时间衰减加权，按需注入当前上下文。

## 4. 记忆控制器与主Agent编排

### 4.1 主Agent职责
主Agent不执行具体业务逻辑，而是作为**编排者与记忆守护者**：
1. **任务路由**：根据用户指令和Agent能力注册表，快速定位目标Agent（支持关键词、语义、依赖图匹配）。
2. **上下文组装**：为每个即将激活的子Agent构建专用输入上下文，严格遵循裁剪规则。
3. **工作区维护**：更新话题状态，处理事件队列，执行版本控制和一致性检查。
4. **异常管理**：检测Agent间纠缠、冲突，触发仲裁或升级。

### 4.2 记忆控制器组件
- **写入处理器**：每步执行后自动触发，调用轻量模型/规则生成结构化摘要、提取关键事实、分配重要性评分，并执行话题边界检测，将记录归入相应模块和话题。
- **检索与评分器**：基于当前任务，对历史话题块进行多信号相关性评分（语义相似度、实体重叠、时间衰减、因果链匹配），选出高相关块。
- **上下文构建器**：根据预算配额，将当前模块私有记忆、话题工作区相关部分、全局知识检索结果组装成结构化提示模板。
- **遗忘与压缩器**：定期对私有记忆进行摘要压缩，将过时或低重要性记录归档/删除；控制短期记忆容量。

## 5. 关键机制设计

### 5.1 话题块与模块帧隔离
- **模块**作为第一级隔离单元，每个子Agent绑定一个模块ID。
- **话题**为跨模块的协作单元，可能存在多个模块共同参与。
- 默认情况下，**上下文按模块隔离**，即使模块间内容高度相关，也不混合内部日志。
- 跨模块信息交换必须通过**话题工作区的公开输出对象**完成。

### 5.2 相关性判断与上下文配比
当需要为当前任务筛选历史信息时：
- 使用**话题分割算法**（TextTiling、语义边界检测）将全量对话切分为话题块。
- 对每个话题块计算与当前任务的相关性得分，融合语义向量相似度、关键词/实体重叠、时间远近、因果引用强度。
- 上下文窗口按相关性得分分配配额：主导话题获得≥70%容量，中等相关话题仅保留一句摘要，无关话题完全丢弃。
- 支持**主动检索查询**：允许Agent在思考前输出“我需要回忆…”，系统据此二次检索。

### 5.3 模块切换与快照机制
当主Agent决定切换激活的Agent时：
1. 保存当前Agent的**私有快照**（最近K步关键摘要、未解决问题、本地变量）。
2. 该Agent调用`publish()`将公开输出更新到工作区。
3. 加载目标Agent的上次私有快照（如有），并从工作区拉取与其依赖相关的上游输出摘要。
4. 组装目标Agent的专用上下文，注入快照、相关共享数据和任务指令。

若切换过程中产生交叉修改请求，通过工作区中的**事件对象**传递，而非将请求放入对方上下文。

### 5.4 多Agent协同下的上下文纯净性
- 每个Agent的输入上下文固定包含三部分：`[话题全局摘要]` + `[与本Agent相关的共享状态]` + `[私有记忆快照]` + `[当前具体任务]`。
- 严禁将其他Agent的完整思考链、重试日志放入上下文。
- 使用**推送式更新**：当工作区中某Agent依赖的数据发生变更时，主Agent主动通知相关Agent，提供变更摘要，而非让其被动发现。
- **上下文验证回路**：子Agent返回结果后，主Agent执行结构验证、一致性检查、完整性检查，确保结果可信后再写入工作区。

### 5.5 长期记忆与遗忘
- 话题结束后，其共享工作区归档为结构化记录，存储到全局知识库，供未来相似任务检索。
- 私有记忆超过容量阈值时，按重要性评分和最近访问时间进行压缩：高重要性记录保留为详细摘要，低重要性记录丢弃或转为极简标记。
- 全局知识库采用**访问频率淘汰**，长期未检索的记忆降权，最终归档。

## 6. 实现路线图

### 6.1 基础组件
1. **Agent能力注册表**：维护模块ID、能力描述、负责代码路径、关键词、依赖关系，支持语义搜索。
2. **共享工作区存储**：轻量级Key-Value存储（如Redis），支持版本号、事件队列。
3. **向量数据库**：用于全局知识库和话题块语义检索（如FAISS、Milvus）。
4. **轻量嵌入模型**：用于话题分割、相关性评分、实体抽取（如all-MiniLM-L6-v2）。

### 6.2 核心流程实现步骤
1. **定义标准数据结构**：`Episode`、`AgentOutput`、`WorkspaceSnapshot`、`Event`的JSON Schema。
2. **实现记忆写入器**：在每个Agent步骤完成后，异步触发摘要生成、重要性评分、话题边界检测。
3. **实现上下文构建器**：根据模块ID、任务指令、工作区状态，调用检索与评分器，填充上下文模板。
4. **实现主Agent编排循环**：
        while 话题未完成:
        扫描工作区事件队列和Agent状态
        选择下一个激活Agent
        构建专用上下文 → 调用 agent.activate(context)
        验证返回结果 → 更新工作区
        处理新生成的事件
5. **实现快照与恢复**：为每个Agent维护内存级快照字典，支持切出时保存、切入时加载。

### 6.3 优化与扩展
- **微调适配**：使用Agent交互轨迹微调LLM，使其更擅长根据结构化记忆标签聚焦注意力。
- **动态资源分配**：根据任务紧急程度，调整摘要压缩的激进程度和检索深度。
- **监控与自愈**：监控上下文切换频率，当检测到Agent间“震荡纠缠”时自动暂停，生成仲裁摘要提交给人工或协调模块。

## 7. 典型场景推演

### 场景：修复商城主页穿模Bug
1. 用户指令：“商城主页有穿模情况，修复它。”
2. 主Agent解析指令，从能力注册表匹配到`ui_agent_homepage`。
3. 构建该Agent的专用上下文：
- 系统角色与全局约束
- 当前话题：T-fix-overlap
- 共享状态：最近的首页相关代码提交摘要、历史相似问题记录（仅摘要）
- 私有记忆：空（首次激活）
- 任务：分析、定位、修复
4. `ui_agent_homepage`执行，发现根因是购物车Agent错误修改了全局导航栏高度。
5. 修复Agent暂停，保存私有快照（包含当前分析证据），向工作区发布事件：请求购物车Agent回滚修改。
6. 主Agent激活`cart_agent`，为其构建干净上下文：仅包含回滚事件、相关提交日志和其自身私有记忆。
7. `cart_agent`完成回滚，发布新输出。
8. 主Agent重新激活`ui_agent_homepage`，加载其私有快照，并注入“导航栏高度已恢复”的最新状态。
9. `ui_agent_homepage`验证修复，完成任务。主Agent将经验归档至全局知识库。

在整个过程中，各Agent看到的上下文始终保持紧凑、精准，无任何无关历史污染。

## 8. 结论

本文档设计了一套以“模块帧隔离 + 话题共享工作区 + 主Agent编排”为核心的多Agent记忆管理系统。它通过严格的读写分离、相关性裁剪和事件驱动，解决了长上下文下的注意力稀释、跨模块协作污染和频繁切换连贯性难题，为构建可靠、长期稳定的复杂多Agent应用提供了完整的记忆层解决方案。
