# 计划：经验技能质量治理与"技能携带工具"改造

> 目标：解决三个问题——① 学习技能沉淀随意、数量过多、近重复；② 经验需要配套自写脚本时，技能无法携带工具；③ 正文双层序号（`1. 1. xxx`）。
> 参考：Voyager（MineDojo/Voyager）、Anthropic Agent Skills 规范（agentskills.io/specification）、OpenSkills（Geeksfino/openskills）、MUSE-Autoskill（arXiv:2605.27366）、SkillCenter/SkillGate（arXiv:2607.07676）、AutoGPT dream dedup（issue #13387）、ContinualSkillBench（arXiv:2608.03874）。

---

## 0. 现状回顾（已核实的根因）

| 问题 | 根因 | 位置 |
|---|---|---|
| 双层序号 | 渲染时无条件拼 `i+1.`，不剥离模型返回的自带编号 | `backend/internal/bootstrap/evolver.go:234` |
| 技能随意/过多 | 轻量模型产出门槛松（0-2 个/会话）；去重只靠 name 精确匹配 + 向量近邻 | `backend/internal/bootstrap/evolver.go` prompt；`persistOne` |
| 不能携带工具 | 技能模型只有 title/when_to_use/content 三段，无附件/脚本概念 | `store/learned_skills.go`、`server/learned_skills.go`、前端编辑弹窗 |

## 阶段 B：技能质量门禁与去重（1.5 周）

**教训来源**：ContinualSkillBench 发现弱模型会积累大量碎片化、低复用的技能——门禁必须在**写入时**执行，不能依赖每日被动整理；AutoGPT dream 的 issue #13387 同样是 consolidate 产生近重复 paraphrase；SkillCenter 用"LLM 质量分（clarity/accuracy/actionability）+ 阈值发布"的 SkillGate 模式保证语料库近零重复。

**B1. 收紧生成 prompt（写入端）**
- 门槛改为：**必须是从本次会话实际走通/验证过的工艺**，且满足"非显而易见、跨项目通用、有具体步骤"三条件之一即写、否则丢弃；
- 单会话产出上限 2 → **1**；
- 要求模型自检：steps 每条必须是**可执行动作**（动词开头），拒绝"检查/注意/确保"类空泛条目；
- prompt 明确："steps 数组元素不要自带序号"。

**B2. 写入时质量门禁（lightweight gate）**
- 复用现有轻量模型，对产出的技能打 1-5 分（rubric：具体性/可执行性/可复用性），< 3 分丢弃并写 evolution_log（kind=skill_rejected，留审计）；
- 门禁失败不阻塞会话结束流程（降级：直接丢弃）。

**B3. 写入时近重复预检（dedup before persist）**
- 现有逻辑：name 精确匹配 → 向量 cosine ≤ 0.25 走 update。问题：**不同 name 但语义近重复**（如 `cli-tool-acceptance-verification` vs `python-cli-tool-development-and-testing`）漏过；
- 改进：persist 前对 `title + when_to_use` 拼接向量与存量做相似度检索，cosine ≥ 0.9（AutoGPT dream 用的阈值）进入 LLM-judge 确认环节：确认重复 → 走 `skill_update` 合并步骤/坑点（union 去重）；不是重复 → 新建；
- LLM-judge 超时/失败时**保守合并**（宁可合并不可灌水，合并方向参考 MUSE-Autoskill：多技能 → 一个更通用的技能）；
- 合并时正文重渲染（走 `renderLearnedSkillMD`），天然消掉编号问题。

**B4. 整理任务对齐**
- `skill_consolidate.go` 的每日整理复用 B3 的同一套 judge 逻辑，避免两条判定标准。

## 阶段 C：技能携带工具（2 周，本期核心）

**参考**：Anthropic Agent Skills 规范（SKILL.md 目录 + `scripts/` + 渐进披露）与 Voyager（技能即可执行代码，**技能必须被运行验证过才入库**）；执行安全参考 OpenSkills（脚本经沙箱执行，只有输出进上下文）与 MUSE-Autoskill（复用 agent 内置 sandbox 生命周期工具执行，不引入独立引擎）。

**C1. 存储形态改造（对齐标准 Skill 格式）**

```
config/skills_learned/<name>/
├── SKILL.md          # 现有 frontmatter + 正文
├── scripts/          # 可执行脚本（.py/.sh/.js），可选
└── references/       # 参考文档，可选
```

- 落盘从单文件 `<name>.md` 改为目录式（迁移：存量 `.md` 首次加载时自动搬成目录，老路径保留只读）；
- frontmatter 增加字段：`tools: [{path, desc, run}]`（相对路径、用途、运行命令）；保持 name/title/when_to_use/outcome 不变；
- PG `learned_skills` 表：`content_path` 语义不变（指向 SKILL.md），新增 `has_tools BOOL`（列表页可显示"带工具"角标），是否需要 embedding 对 tools desc 单独建向量**先不做**。

**C2. 执行链路（渐进披露第三层）**

- 加载技能时（load_skill）若 frontmatter 有 `tools`，在正文中追加一段"配套工具"说明：每个脚本的路径 + 运行方式 + 一句用途；
- agent 侧执行：复用现有 RunCommand/sandbox 工具运行 `scripts/` 下脚本，**脚本输出才进上下文**（OpenSkills 模式）；脚本执行前 `chmod +x`，Windows 下 `.sh` 走 git-bash、`.py` 走项目 Python；
- 安全底线：脚本只在技能目录内读写（沿用现有 sandbox 路径合规检查，对应你已有的"工具调用沙箱路径合规处理"技能的场景），执行前把脚本路径写入 evolution_log 审计。

**C3. 沉淀链路：经验带脚本时自动生成工具**

- evolver prompt 扩展：技能 JSON 增加可选 `tools: [{filename, language, code, desc}]` 字段——当会话中**实际用过某个自写脚本并成功**时，要求模型把脚本固化进技能；
- 轻量模型只生成小脚本（≤ 60 行），超长脚本只沉淀"步骤 + 复现指引"不写 code；
- 落盘时 `code` 写入 `scripts/<filename>`，frontmatter 自动补 `tools` 清单；
- **验证**（借 Voyager 思路）：写入前对脚本做一次冒烟执行（有主语言运行时且声明了 `run` 时），执行失败 → 脚本降级为正文附录代码块，不生成 scripts/ 目录。

**C4. 前端**

- 技能卡片：有 tools 的技能显示"⚙ 带工具"角标；
- 编辑弹窗：正文下方增加"配套脚本"区（列表：文件名/用途/运行命令；支持查看内容、删除；暂不支持在线新建——新建走沉淀链路，编辑只做管理，降低范围）；
- API：`GET /learned-skills/:name` 增加 tools 字段；`PUT` 支持 tools 编辑。

**C5. 与标准技能体系的关系**

- `types.Skill` 已有 `Path`，让内置技能加载器同样支持目录式 SKILL.md（目前只有 learned 技能改造；内置技能带 scripts 是后续独立迭代）；
- 长期：learned 技能与内置技能合并为同一套目录式规范，learned 只是 source 不同。

## 里程碑与验收

| 阶段 | 验收标准 |
|---|---|
| A | 存量清洗报告零"1. 1."残留；新沉淀技能回归测试通过 |
| B | 造 3 组近重复会话，2 组被判合并、1 组新建；低质技能（空泛 steps）被拒绝并留日志；技能库周增量下降 ≥ 50% |
| C | 一次"会话中用脚本完成任务"→ 技能带 `scripts/` 落盘 → 新会话 load_skill 后 agent 能执行该脚本拿到输出；冒烟失败正确降级 |

## 风险

- **LLM-judge 增加延迟/成本**：门禁和 judge 都走轻量模型，且只在会话结束后触发；judge 失败一律保守合并或丢弃，不产生半成品；
- **脚本安全**：固定为"仅技能目录内可写、需审计日志"，不做任意路径执行；
- **迁移**：存量 `.md` → 目录搬迁失败时回退只读老文件，不丢数据。
